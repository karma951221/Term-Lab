# 범위

> 상태: 초안 · 최종수정: 2026-08-29

## 사내 시스템과의 관계

terms-studio 는 **사내 약관시스템의 clone 을 더 나은 버전으로 다시 만드는 것**이다.

| | |
|---|---|
| **목적** | 대체 |
| **개발** | 기존과 **완전히 별개**로 진행 — 코드·DB·인프라 연동 없음 |

사내 시스템의 기능은 **참조 기준**이다. 무엇을 만들지 정할 때 거기를 보되, 연동하지 않는다.

## 단계

### MVP — 알파Plus 약관 생성

**`(무)알파Plus보장보험2604` 의 약관을 이 시스템으로 생성한다.** 이것이 MVP 의 전부다.
**보통약관 + 특별약관 전부**다 (2026-08-29 결정).

- 원문 자료가 확보돼 있다 → [[_자료/보통약관_원문]] · [[_자료/보통약관_분석]]
  (terms-lab `local/` 에서 복사, 2026-08-29. 원본은 terms-lab 에 그대로 있다)
- terms-lab 도 같은 상품으로 관통을 검증했다. 당시 확인 사실(무엇이 ✅ 였는지)은
  [[_archive/01_기획/상품모델링_기획]] §0.1 이 갖고 있다 — 소재 파악용으로만 참조.

### 향후 — 전체 상품 + 별지 자동생성

1. **전체 상품**으로 확대한다.
2. 약관 외에 **별지(사업방법서)까지 자동생성**한다.

> 별지가 로드맵에 있다는 사실이 지금의 설계에 거는 제약 —
> 조립 파이프라인이 「약관 문서 전용」으로 굳으면 안 된다.
> 같은 모델링 데이터에서 **다른 종류의 문서**가 나와야 한다. → [[03_설계/아키텍처]] 요구사항

## 다루는 것 (MVP)

- 구분자 정의와 유효값 — **코드가 아닌 데이터로**
- 모델링과 구분자의 타입 일치 (폼 = 구조체)
- 알파Plus **보통약관 + 특별약관** 모델링 → 약관 조립 → **화면 미리보기**

## 다루지 않는 것

- 사내 시스템과의 연동 (영구)
- 사내 시스템 기존 데이터의 마이그레이션 — 대체 시점의 일이다.
  **단, 버리는 결정이 아니다** → Q1
- 별지(사업방법서) — 향후 단계

## 나중으로 미루는 것

- **보험료가벼운납입형** (2026-08-29) — 판매중지 가능성 + 지엽적. 모델의 「번호 없는 세목 선택지」 자리는 유지
- **기본계약이 없거나 복수인 상품** (2026-08-29) — MVP 는 기본계약 정확히 1개
- **다단 파생** (2026-08-29) — 파생이 파생을 읽는 식
- **별표 내용 출력** (2026-08-29) — MVP 는 별표 목록 추가·조회 + 본문 참조까지
- **표지·목차 등 책자 앞부분 문서** (2026-08-29) — MVP 는 보통약관 + 특별약관만
- **산출물 스냅샷 회귀 비교** (2026-08-30) — 시점 스냅샷 vs 재산출 비교로 수정 영향도를 보는 기능
- **정의 변경·삭제 정식 규칙 + 이력·개정 규칙** (2026-08-30) — MVP 는 잠정 규칙([[01_기획/구분자_기획]])
- **인증·권한 분리** (2026-08-30) — 현재 1인 사용. 향후 다인+권한. 스키마가 사용자 개념을 원천 배제하지 않게만 유지
- **동적 표** (2026-08-31) — 반복·조건을 품는 표(지급금액표 등). MVP 이후 동적표 기획에서.
  문면 저장 모델의 노드 자리만 확보 → [[01_기획/문면_기획]]. ⚠ [[04_실행/개발순서]] P7 재조정 시 반영
- **조 하위 그룹 구조(그룹 노드)** (2026-08-31) — 실물에 존재. 저장 모델이 허용 자식 규칙
  확장으로 수용 (ADR-0012 — 구조 변경 없이 끼울 수 있게 설계됨)
- **공용조항 중첩** (2026-08-31) — MVP 이후 구현 확정 (P3 의 「보류」에서 로드맵으로 승격).
  생략 자동 판정(ADR-0014)의 동일성 확보 전략을 강화

- `.docx` 등 최종 산출물 서식 — 관통의 종점은 화면 미리보기다
- 전체 상품 확대

  아니면 「그때 가서 변환」으로 충분한지. → [[03_설계/데이터모델]] 에서 결정
- **Q2. 체증·체감납 인수 시나리오([[문제정의]] S4)를 알파Plus 관통에서 함께 검증할 수 있는가,
  별도 사례가 필요한가.**
