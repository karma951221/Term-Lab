# 체증·체감납 인수 시나리오

> 상태: 초안 · 최종수정: 2026-09-01
> 관련 기획: [[00_시작/문제정의]] S4 (인수 시나리오 1호) · [[00_시작/도메인모델]] §6 불변 규칙 · [[01_기획/구분자_기획]]

기준 사례의 재현이다: 사내 시스템에서 `체증·체감납 여부`와 `보험료 가벼운 납입형 여부`가
중복 채번됐다 — 개념적으로 다르지만 현재 운영상 값이 항상 같은 두 구분자.
이 시스템에서 같은 상황을 만들면 후자가 별도 채번되지 않아야 한다.
근거 규칙: **구분자는 문면이 묻는 개념으로 딴다** — 지금 어떤 세목·운영 형태로 팔리는지는
구분자 정의에 넣지 않는다.

## 시나리오 1 — 개념 구분자 채번: 체증·체감납여부
**전제**: 빈 마스터.
**흐름**:
1. 상품 레벨 boolean 구분자 「체증·체감납여부」 채번 — 문면이 묻는 개념(보험료가 기간에 따라 체증·체감하는 납입 구조)으로 딴다.
2. 약관 문면의 조건식이 이 구분자를 참조한다.
**기대 결과**: 상품 구조에서 직접 결정되는 개념이 구분자가 된다. 값의 출처가 하나다.
**경계·오류**: 개념이 아닌 판매 형태의 이름(「~형 여부」)으로 개념 구분자를 따려는 시도가 이후 시나리오의 반례다.

## 시나리오 2 — 「보험료 가벼운 납입형 여부」 채번 시도 → 별도 채번되지 않음
**전제**: 「체증·체감납여부」 존재. 현재 체증·체감납 상품을 「가벼운납입형」 세목으로만 판매 중 — 두 값이 운영상 항상 같다.
**흐름**:
1. 유저가 상품 레벨 boolean 구분자 「보험료 가벼운 납입형 여부」 채번 시도.
2. 시스템이 「무엇을 근거로 결정되는가」를 가르게 한다 — 이 값은 상품 구조에서 직접 결정되지 않고 「체증·체감납여부」에서 유도되는 이름이다.
3. 직접 구분자 채번 대신 두 경로로 유도된다 — (a) 운영 형태라면 세목 선택지 (시나리오 3), (b) 값으로 필요하다면 파생 (시나리오 4).
**기대 결과**: 직접 구분자 「보험료 가벼운 납입형 여부」가 생기지 않는다 — S4 통과 조건.
**경계·오류**: ⚠ 미결: 유도의 메커니즘 — 시스템의 후보 제시인가, 규칙 강제인가 (문제정의 Q2). ⚠ 미결: 유저가 유도를 무시하고 직접 채번을 강행할 수 있는가, 강행 시 무엇이 남는가.

## 시나리오 3 — 운영 형태는 세목 선택지로
**전제**: 세목유형 「납입형태」 존재 (도메인모델 §1 — 종·형으로 구분하지 않는 세목의 반례 사례).
**흐름**:
1. 「기본납입형」·「가벼운납입형」을 납입형태 세목유형의 선택지로 등록 — 구분자 채번이 아니다.
2. 상품이 유효 조합을 명시 등록하고, 계약 관점의 「가벼운납입형」 여부는 세목 구성이 답한다.
3. 문면이 체증·체감납이라는 개념을 물을 때의 조건식은 세목 이름이 아니라 구분자 「체증·체감납여부」를 참조한다.
**기대 결과**: 개념(구분자)과 운영 형태(세목 선택지)의 자리가 갈린다 — 정의가 섞이지 않는다.
**경계·오류**: 문면이 세목의 존재·표기명을 직접 묻는 문구(종별 문구 유즈케이스)는 별도 메커니즘 — [[00_시작/도메인모델]] §3 미결로 관리 중, 이 시나리오의 범위 밖.

## 시나리오 4 — 값으로 필요하면 파생으로
**전제**: 시나리오 2 상태. 조건식 어딘가가 「보험료 가벼운 납입형 여부」라는 이름의 값을 요구.
**흐름**:
1. 직접 구분자 대신 파생 구분자로 정의 — 값은 「체증·체감납여부」에서 유도되고, 식은 데이터로 저장된다.
2. 조건식이 이 파생을 참조한다.
**기대 결과**: 상품구조가 바뀌어 두 개념이 갈라지면 파생의 식만 고치면 된다 — 각 상품의 모델링은 손대지 않는다.
**경계·오류**: ⚠ 미결: 이 파생의 식 형태 — 확정된 파생은 집계 6종(any·all·sum·count·exist·not exist) + 부착점 하위 트리 범위인데, 같은 상품 레벨 값을 그대로 유도하는 별칭형 파생이 문법상 허용되는가.

## 시나리오 5 — 갈라지는 날: 새 상품구조 등장
**전제**: 시나리오 1~4 완료 상태에서, 체증·체감납이지만 가벼운납입형이 아닌 새 상품구조가 등장 — 두 값이 처음으로 갈라진다.
**흐름**:
1. 구분자 「체증·체감납여부」는 그대로 — 값이 채워지는 경로가 바뀌어도 구분자는 그대로다.
2. 새 상품의 세목 구성과 파생식만 수정한다.
3. 기존 상품담보는 스냅샷이라 영향이 없다.
**기대 결과**: 재채번·데이터 이관 없이 갈라짐을 흡수한다.
**경계·오류**: 시나리오 2에서 중복 채번을 막지 못했다면 이 시점에 되돌릴 수 없다 — 각 구분자로 이미 모델링한 건들 때문에 지울 수 없다 (문제정의 「탐지가 아니라 예방」). 이 파일이 인수 시나리오 1호인 이유.
