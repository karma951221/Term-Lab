# 데이터모델

> 상태: 초안 · 최종수정: 2026-09-05
> 정본은 `src/db/schema/*.ts` (drizzle). 이 문서는 무엇이 어디 사는지의 지도다.

## 저장 구조 — 원칙

- **코드(불변)와 id(uuid)는 다르다.** 코드는 참조·식·저장의 정본(ADR-0005), id 는 저장소 행 식별자.
  코드는 `code_sequences (kind, scope, next)` 에서 원자적으로 채번하고 삭제된 순번은 재사용하지 않는다.
  구분자 `D0001` · 필드 `F01`(구조체 안) · enum `E0001` · enum 값 `V01` · 공용조항 `C0001` · 옵션 `O01` · 담보속성 `A0001` · 유효값 `V01`.
  별표만 유저 입력 코드(리뷰 대상 R5).
- **값 자리는 한 테이블이다.** `entity_values (owner_kind, owner_id, discriminator_code, field_code, value jsonb)` —
  **미입력 = 행 없음**(ADR-0004), null 값 행은 없다. 소유자는 부착 5레벨 실체(product · plan · coverage · subCoverage · benefit)와
  탑재 스냅샷 실체(productCoverage · productSubCoverage · productBenefit · productPlan). 탑재 = 행 복사(ADR-0002).
- **선택적 노출 부착도 한 테이블이다.** `entity_attachments (owner_kind, owner_id, discriminator_code)`. 부착 여부 = 정의의 `always_exposed` ∨ 이 행.
- **영역 간 FK 는 걸지 않는다.** 값·부착 테이블은 소유자 id 를 FK 없이 갖는다. 삭제 연쇄는 서비스가 한다.
  영역 안(담보 → 세부보장 → 급부, 공용조항 안 옵션 등)에는 FK cascade 를 쓴다.
- **문면은 문서 1행 = 트리 jsonb 1건.** 노드 id 는 트리 안에서 유일. 번호는 저장하지 않는다(ADR-0012).
- 모든 테이블에 감사 자리(`created_at/updated_at/created_by/updated_by`) — 이력·개정 기획(2차기획 목록)의 발판.
- 표준 Postgres 만. PGlite 전용 기능 금지 (서버 Postgres 이관 대비).

## 스키마 (영역별 파일)

| 파일 | 테이블 | 비고 |
|---|---|---|
| `auth.ts` | `users`(name UQ, role) · `sessions`(token PK, user_id, expires_at) | ADR-0019. 로그인은 이름 선택 최소형 |
| `catalog.ts` | `discriminators`(code UQ, kind scalar/struct/const/derived, level, always_exposed, scalar_type, default_value, const_value, expression) · `struct_fields`(discriminator_id FK, code, type jsonb, default_value, order) · `enums` · `enum_values` · `code_sequences` | 기본값은 프리필 전용 컬럼 |
| `values.ts` | `entity_values` · `entity_attachments` | 위 원칙 |
| `coverage.ts` | `coverages`(name UQ, document_id) · `sub_coverages`(coverage_id FK cascade, order, UQ name) · `benefits`(sub_coverage_id FK cascade, order, UQ name) | 이름은 뼈대 속성 |
| `common.ts` | `clauses`(code UQ, mode, body jsonb, options jsonb, required_discriminators jsonb, required_attributes jsonb) | 요구 구분자는 저장 시 계산 |
| `document.ts` | `documents`(kind special/general, owner_id UQ, title, general_document_id, tree jsonb) · `appendices`(code UQ, name) | 담보 1 : 담보약관 1 |
| `product.ts` | `attribute_kinds` · `attribute_values`(naming prefix/suffix) · `products`(general_document_id) · `plan_options`(axis, number, name, type discriminator) · `product_plans`(key) · `product_plan_options` · `product_coverages`(coverage_id, coverage_name, combination_key UQ) · `product_coverage_attributes` · `product_coverage_nodes`(스냅샷 노드 ↔ 마스터 노드 대응) · `product_coverage_plans` · `product_base_contracts`(복수 허용) · `special_groups`(general_document_id 자리) · `special_group_members` · `clause_option_overrides`(scope kind/id, clause_code, options jsonb) | 기본계약 「정확히 1개」는 검증 규칙 |

## 마이그레이션 원칙

- 스키마는 TS 코드가 정본. `npm run db:generate` 로 `drizzle/` 에 SQL 을 생성하고 `db:migrate`/시드가 적용한다.
- 테스트는 마이그레이션 파일에 의존하지 않는다 — `pushSchema` 로 스키마 코드에서 바로 DDL 을 만든다.
  마이그레이션 파일은 실제 파일 DB(`.data/pgdata`)와 배포용이다.
- 개발 DB 는 PGlite 파일, 프로덕션은 Postgres 호환(미정). 같은 마이그레이션을 그대로 쓴다.
- **Q1(마이그레이션 대비)**([[00_시작/범위]]): 코드 불변 + 값 테이블 단일 + 감사 자리로 기존 데이터 이관의 원천 봉쇄는 없다. 변환 규칙은 대체 시점에.
