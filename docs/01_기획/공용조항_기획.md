# 공용조항 기획

> 상태: 초안 · 최종수정: 2026-08-30
> 대응 도메인모델: [[도메인모델]] §3 문면

## 해결하려는 것

담보약관마다 공통적인 문구(특별약관의 소멸, 준용규정 등)를 매번 다시 쓰지 않고,
**공통 템플릿(공용조항)으로 정의해 가져다 쓴다.**

## 실물 근거 (알파Plus 특약 10건, 2026-08-30)

- 「특별약관의 소멸」 조: 10건 전부 존재
- 「준용규정」 조: 10건 전부 존재
- **내용이 완전 동일하지는 않다** — 예: 소멸 조가 사망 담보에서는 「사망보험금 지급사유 발생으로 소멸」,
  타 담보에서는 「피보험자 사망으로 소멸 + 계약자적립액·미경과보험료 지급」으로 다르다.
- 조 번호는 특약마다 다르다 (제3조/제5조 등) — 번호는 계산값이므로 문제 아님.

## 동작 정의

- **참조다** (2026-08-30 확정). 문장은 공용조항 마스터에 살고, 사용처에는 연결만 있다.
  공용조항을 고치면 쓰는 곳 전부에 전파된다 — 문면 마스터 소유 원칙과 같은 결.
- **사용처는 보통약관과 담보약관 둘 다다** (2026-08-30 확정). 담보약관 전용이 아니다.
- **다를 수 있는 부분은 옵션이다** (2026-08-30 확정). 공용조항 정의에 「가능한 옵션」을 두고,
  각 사용처(보통약관·담보약관)에서 옵션을 선택한다. 사용처가 문장을 자유 수정하는 것이 아니다.
- **옵션 선택은 수동이다** (2026-08-30 확정). 자동으로 갈려야 하는 자리는 옵션이 아니라
  **조건식(if)으로 만든다** — 공용조항도 일반 문면처럼 조건 분기를 품을 수 있다.
- **공용조항은 두 가지 모드가 있다** (2026-08-30 확정).
  - **inline** — 문장 안에 삽입되는 문구 단위.
  - **block** — **항 또는 항 목록**으로 구성되는 단위.
  - **조는 항상 사용처 소유다** (2026-08-30 확정). block 은 항상 항 단위이므로 조의 소유를 고려할
    필요가 없다 — 담보약관에 쓸 내용을 다른 곳에서 참조하는 것뿐이다. 조 제목 포함 block 은 없다.

- **큰 차이는 별도 공용조항으로 딴다** (2026-08-30 확정). 항 구성 자체가 다른 수준(예: 소멸 조의
  사망 담보형 vs 일반형)이면 옵션으로 우겨넣지 않고 공용조항을 따로 만든다.
  옵션은 문구 수준의 대안 선택에 쓴다.

## 규칙과 경계

- **순서 보존** (2026-08-30 확정) — 한 조 안에서 직접 쓴 항과 block 참조가 섞일 수 있고,
  출력 문서는 그 배치 순서 그대로 나온다.
- **중첩 금지 (MVP)** (2026-08-30 확정) — 공용조항 안에 공용조항을 넣을 수 없다.
  현행 시스템은 허용하나 구현이 매우 까다롭고 버그가 많았다 — 일단 보류.

- **조건식의 평가 문맥은 사용처가 결정한다** (2026-08-30 확정).
  담보약관에서 쓰이면 공용조항 안의 담보 레벨 구분자 조건은 그 담보 문맥에서 결정되고,
  상품 레벨 구분자 조건은 담보약관 단계에서는 결정되지 않는다(상품 조립 때 결정).
