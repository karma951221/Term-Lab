# 문면 기획

> 상태: 합의 · 최종수정: 2026-08-31
> 대응 도메인모델: [[도메인모델]] §3 문면 · 개발 단계: [[개발순서]] P4

## 해결하려는 것

담보약관·보통약관 **마스터 문면을 작성·저장하는 방식**을 정한다.

분기의 책임이 마스터 문면에 있으므로([[ADR-0003-문면-마스터소유-분기책임]])
이 화면이 모든 탑재 케이스의 문면을 조건문으로 미리 감당해야 한다 —
조·항 구조 안에 치환·조건·반복이 **데이터로 앉는 모양**이 이 기획의 본체다.
[[도메인모델]] §7 미결 「문면 저장소의 저장 단위 상세」가 여기서 답해졌다.

기획 범위는 [[개발순서]] P4 의 네 줄: ① 조·항·호·목 편집 + 조건 분기(인라인 포함)
② 공용조항 사용 ③ 부분 사전평가 + 뷰 토글 ④ 보통약관 마스터 + 조연결 최소형.

## 확정된 전제 (도메인모델·기존 기획에서)

- **문면은 마스터 소유.** 특약 문서 N : 담보 1. 보통약관도 마스터 문서(여러 벌 · 상품이 선택).
  상품 간 차이는 값이 가른다 — 상품별 문장 수정은 없다.
- **동적 처리는 3종이 전부**: 치환(슬롯) · 조건 분기 · 반복. 반복은 MVP 포함이나 구현은 P7(관통 2).
- **조건 분기는 if / elif / else + 인라인(문장 중간) 필수** — 갱신형 수술비 실물로 실증
  (어구 차이 「계약일↔최초계약일」, 조 단위 on/off, 준용규정 내용 차이).
- **조건식 참조 범위**: 상품 레벨 구분자 + 담보 레벨 구분자.
  보통약관 문맥의 담보 레벨 참조는 기본계약으로 해소([[ADR-0011-보통약관문맥-기본계약]]) —
  해소는 조립 시점이라 보통약관 편집 화면에서 담보 레벨 조건은 미결로 남는다.
- **공용조항 사용은 기획 완료** ([[공용조항_기획]] 합의) — 참조 · inline/block · 옵션 수동 선택 ·
  배치 순서 보존 · 붙이는 시점 부착 검사. 에디터는 이 기획을 소비할 뿐 새 결정이 없다.
- **문면은 이름을 직접 부르지 않는다** — 이름 치환 슬롯은 없고, 치환은 값 참조뿐.
  상품담보명·상품명은 문서 제목 등 메타 자리 전용.
- **반복의 순회 소스는 모델링 구조** — `for 세부보장 in 세부보장목록`, 문맥 담보의 하위 목록.
  이름은 뼈대 속성이라 `세부보장.세부보장명` 내장 경로로 찍는다 ([[담보_기획]]).
- **const 구분자 참조** (MVP string 만 — 표시 형식 변환 없음).
- **같은 모델링 데이터에서 다른 문서 종류(별지)가 나와야 한다** ([[범위]]) —
  저장 모델이 「약관 조문 전용」 개념에 굳으면 안 된다는 아키텍처 제약.

## 저장 단위 — 문서 노드 트리 (2026-08-31 확정 → [[ADR-0012-문면-노드트리-구조편집기]])

문서 = 노드 트리. 노드를 세 부류로 가른다.

| 부류 | 노드 (MVP) | 비고 |
|---|---|---|
| 구조 노드 | 문서 · 조 · 항 · 호 · 목 | **호·목 포함 확정** — 실물에 실사용 |
| 블록 자리 동적 노드 | 조건 블록(if/elif/else) · 반복 블록 · 공용조항 block 참조 | 구조 노드가 서는 자리에 대신 선다 — 조 단위 on/off 가 이것 |
| 인라인 노드 | 텍스트런 · 슬롯(값 참조) · 인라인 조건 · 인라인 반복 · 조 참조 슬롯 · 별표 참조 슬롯 · 공용조항 inline 참조 | 문장 흐름 안에 선다 |

- **저장 모델은 깊이·노드 종류를 고정하지 않는다.**
  실물에는 조 하위에 다시 **그룹별 조·항·호·목**이 오는 구조가 있다 — 그룹 노드는 MVP 이후
  개발하지만, 저장 모델이 「조>항>호>목 4단」으로 굳어 있으면 그때 못 끼운다.
  트리는 일반 트리로 두고, **노드 종류별 허용 자식은 규칙**으로 건다 — MVP 규칙이
  조>항>호>목이고, 그룹 노드 추가는 규칙의 확장이지 저장 구조 변경이 아니다.
- **표는 MVP 이후 「동적표」 기획으로 유예** (2026-08-31 결정). 지급금액표처럼 반복(세부보장별 행)·
  조건(종별 행)을 품는 표가 대상이다. 노드 자리(구조 노드의 한 종류가 된다)만 인지해 둔다.
  ⚠ [[개발순서]] P7 「반복문 + 표 → 관통 2: 수술비」와 맞물린다 — P7 재조정 시 반영.
- **조의 메타는 조 명 · 조연결 뿐이다.** 그 외 메타는 두지 않는다.
- **번호는 저장하지 않는다 — 계산값이다.** 조 번호·항 번호는 조건 해소 후 남은 노드에
  순서대로 매긴다. 실물 실증: 갱신형 수술비의 조 하나 추가로 이후 조 번호가 밀린다.
- 이 트리가 조립(P6)의 입력이고, 조립 결과 문서트리도 순수 데이터다 —
  산출물 스냅샷 회귀 비교([[범위]] 유예 항목)의 기반이 된다.

## 동적 노드의 문법 (2026-08-31 확정)

- **블록 조건의 중첩은 허용, 인라인 조건의 중첩은 금지.** 문장 안 이중 분기가 필요하면
  항을 쪼개 블록 조건으로 푼다. 인라인 중첩은 편집 표시·사전평가 톤다운의 복잡도 폭발 지점이다.
- **식 언어는 한 벌이다** (→ [[ADR-0013-식언어-통일]]). 문면 조건식과 파생식([[도메인모델]] §2)이
  같은 문법·파서·평가기를 쓴다 — 참조 경로 + 비교 + and/or + 집계 6종. 조건식은 결과가
  boolean 인 식일 뿐이다. 요구 구분자 자동 추출([[ADR-0010-공용조항-참조바인딩]])도 같은 기계를
  쓰고, 종별 문구의 세목 존재·개수 조건(P7)도 이 언어에 얹는다.
- **인라인 반복 노드가 있다.** `for` 가 인라인 원소를 돌며 찍고 결과가 문장 흐름 안에 앉는다 —
  실물: 제1조(보장범위)의 세부보장명 나열 「1종수술, 2종수술, …, 7종수술」. 블록 반복과
  별개의 노드 종류다. 구현은 P7, 노드 자리는 확정.
- 블록 반복은 항 이하 구조 노드를 품는다 (표 행은 동적표 기획으로 유예).

## 참조 슬롯 — 조·별표 (2026-08-31 확정)

번호는 계산값이므로 **본문에 번호를 텍스트로 박으면 밀리는 순간 오참조가 된다.**
번호를 부르는 자리는 전부 참조 슬롯이다.

- **조 참조 슬롯** — 조의 id 를 저장하고, 렌더 시 그 조의 계산된 번호(+조 명)를 찍는다.
  같은 문서 안의 조 참조와 보통약관 조 참조(담보약관에서) 두 종. 대상 조가 분기로
  사라지면 조립 오류 + 좌표 보고.
- **별표 참조 슬롯** — 별표는 **전상품 superset 마스터 + 불변 코드**다. 문면에는 코드 참조만
  들어간다. 책자 조립 시 **그 책자에서 참조된 별표만 모아 나열 순서대로 번호를 계산**한다 —
  같은 별표라도 상품(책자)마다 별표 번호가 다를 수 있다. 번호는 책자별 계산값이다.
- [ ] 렌더 표기 형태(「제3조(보험금의 지급사유)」·「【별표13(화상 분류표)】」 등)는
      구현 전 실물 조사로 확정한다.

## 참조 무결성 (2026-08-31 확정 — 타협 불가 요구)

현행 시스템의 최대 고통 하나가 **참조가 꼬이거나, 참조를 허용했다가 문서 생성이 깨지는 것**이다.
재발 방지는 요구사항이다:

- **참조는 그래프다.** 구분자 참조 · 공용조항 참조 · 조 참조 · 별표 참조 전부 —
  저장 구조가 그래프로서 검증 가능해야 한다: **순환 참조 탐지 · 고아(어디서도 참조되지 않는)
  구분자 탐지.** 그래프 표현·검증의 상세는 설계([[03_설계/아키텍처]]) 몫.
- **관계정보 뷰는 MVP 필수.** 어떤 구분자·공용조항이 어느 담보약관·보통약관에 쓰이는지
  역방향으로 보는 화면. [[구분자_기획]] 의 사용처 추적(역인덱스, P1)을 화면으로 격상한 것이고,
  [[문제정의]] S3(값 하나를 짚으면 출처가 하나)의 역방향이다.
- 원칙은 두 겹: **참조를 추가하는 시점에 검증**(공용조항 부착 검사와 같은 결) +
  **조립 시점 오류 + 좌표 보고.** 조용히 틀린 문서가 나가는 경로를 남기지 않는다.

## 사전평가 (2026-08-31 확정)

- 담보약관 편집 화면의 사전평가 값 출처는 **담보 마스터에 입력된 값**이다.
  상품 레벨 조건은 미결(조립 때 결정)로 표시한다.
- 죽은 가지의 검토는 **전체 뷰 토글**로 한다. 가상 값 시뮬레이션은 만들지 않는다 —
  수많은 구분자 값을 사람이 일일이 눌러볼 수 없다.
- **상품담보 미리보기** (기존 시스템 차용) — 이미 모델링된 상품담보를 선택하면 그 스냅샷 값으로
  문면을 평가해 미리보기한다. 필요한 구분자가 전부 실값으로 채워진 문맥이다. 상품·탑재(P5)
  이후 합류.

## 보통약관 마스터와 조연결 (2026-08-31 확정)

- 보통약관 마스터 화면은 **목록 + 선택의 최소형** — MVP 관통은 알파Plus 1벌이면 된다.
- 조연결 최소형 = 담보약관의 각 조에 대응 보통약관 조를 고르는 UI 까지.
  조합 옵션 정의·준용 문구 자동 생성은 P7 준용 기획으로.
- **「생략하기」는 자동 판정이다** (→ [[ADR-0014-생략-자동판정]]). 조립 시점에 조건 해소가 끝난
  렌더 결과를 (조 명 제외) **리터럴 비교** — 띄어쓰기 하나 달라도 다르다고 판정한다.
  탑재분마다 값이 달라 동일 여부가 갈릴 수 있고, 자동 비교는 이를 탑재분별로 정확히 처리한다.
  - 따름 전략: **동일성은 우연에 맡기지 않고 공용조항 참조로 구조적으로 확보한다** —
    같은 문구는 같은 공용조항을 참조하므로 리터럴 동일이 보장된다. 현행 시스템도 같은 방식.
  - **공용조항 중첩은 MVP 이후 구현을 확정** (2026-08-31 — [[공용조항_기획]] 의 「보류」에서
    로드맵으로 승격). 중첩은 이 동일성 확보 전략을 강화한다.

## 경계 (P4 가 만들지 않는 것)

- 준용 규칙 세부 (P7) — 조연결은 「대응 조 선택 + 생략하기」까지.
- 반복문 구현 (P7 관통 2) — 저장 모델의 노드 자리(블록·인라인 반복)만 P4 에서 확보.
- 동적 표 (MVP 이후 — [[범위]]) · 조 하위 그룹 노드 (MVP 이후) · 공용조항 중첩 (MVP 이후).
- 종별 문구 메커니즘 (P7) — 세목 존재 조건 + 종형명 치환. 식 언어([[ADR-0013-식언어-통일]])에 얹는다.
- 파생 구분자 식 편집 (P7).
- 원문 이관 자동 분해 (2026-08-31 결정 — 만들지 않는다). 이관은 수동이다:
  단순 붙여넣기로 될 일이 아니라, 공통 항을 공용조항으로 뽑고 조건식을 설계하는
  **기획 판단 작업**이라 자동 분해의 실익이 적다.
- 표지·목차·`.docx` ([[범위]]).

## 화면

- **편집기는 구조 편집기다** (2026-08-31 확정 → [[ADR-0012-문면-노드트리-구조편집기]]) —
  조·항·호·목을 블록으로 추가·이동하고, 문장은 블록 안에서 편집하며, 슬롯·인라인 조건은
  문장 안에 칩으로 삽입한다. 자유 텍스트 + 마크업 방식은 기각 (쓰기 불편 + 톤다운·검사 UI 불성립).
- 문면 편집기 · 관계정보 뷰 화면기획은 [[02_UI]] 에 딴다.
  사전평가 뷰 토글·미결 표시는 [[02_UI/디자인원칙]] 과 합류.
