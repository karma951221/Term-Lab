# 문면 기획

> 상태: 초안 (뼈대 — 쟁점 6건 논의 대기) · 최종수정: 2026-08-31
> 대응 도메인모델: [[도메인모델]] §3 문면 · 개발 단계: [[개발순서]] P4

## 해결하려는 것

담보약관·보통약관 **마스터 문면을 작성·저장하는 방식**을 정한다.

분기의 책임이 마스터 문면에 있으므로([[ADR-0003-문면-마스터소유-분기책임]])
이 화면이 모든 탑재 케이스의 문면을 조건문으로 미리 감당해야 한다 —
조·항 구조 안에 치환·조건·반복이 **데이터로 앉는 모양**이 이 기획의 본체다.
[[도메인모델]] §7 미결 「문면 저장소의 저장 단위 상세」가 여기서 답해진다.

기획 범위는 [[개발순서]] P4 의 네 줄: ① 조·항·호·목 편집 + 조건 분기(인라인 포함)
② 공용조항 사용 ③ 부분 사전평가 + 뷰 토글 ④ 보통약관 마스터 + 조연결 최소형.

## 확정된 전제 (도메인모델·기존 기획에서)

- **문면은 마스터 소유.** 특약 문서 N : 담보 1. 보통약관도 마스터 문서(여러 벌 · 상품이 선택).
  상품 간 차이는 값이 가른다 — 상품별 문장 수정은 없다.
- **동적 처리는 3종이 전부**: 치환(슬롯) · 조건 분기 · 반복. 반복은 MVP 포함이나 구현은 P7(관통 2).
- **조건 분기는 if / elif / else + 인라인(문장 중간) 필수** — 갱신형 수술비 실물로 실증
  (어구 차이 「계약일↔최초계약일」, 조 단위 on/off, 준용규정 내용 차이).
- **조건식 참조 범위**: 상품 레벨 구분자 + 담보 레벨 구분자.
  보통약관 문맥의 담보 레벨 참조는 기본계약으로 해소([[ADR-0011-보통약관문맥-기본계약]]) —
  해소는 조립 시점이라 보통약관 편집 화면에서 담보 레벨 조건은 미결로 남는다.
- **부분 사전평가 + 사전평가 뷰 ↔ 전체 뷰 토글** (2026-08-30 확정 — MVP).
  미입력을 만난 분기는 톤다운이 아니라 **「미결」 표시** ([[구분자_기획]]).
- **공용조항 사용은 기획 완료** ([[공용조항_기획]] 합의) — 참조 · inline/block · 옵션 수동 선택 ·
  배치 순서 보존 · 붙이는 시점 부착 검사. 에디터는 이 기획을 소비할 뿐 새 결정이 없다.
- **문면은 이름을 직접 부르지 않는다** — 이름 치환 슬롯은 없고, 치환은 값 참조뿐.
  상품담보명·상품명은 문서 제목 등 메타 자리 전용.
- **반복의 순회 소스는 모델링 구조** — `for 세부보장 in 세부보장목록`, 문맥 담보의 하위 목록.
  이름은 뼈대 속성이라 `세부보장.세부보장명` 내장 경로로 찍는다 ([[담보_기획]]).
- **const 구분자 참조** (MVP string 만 — 표시 형식 변환 없음).
- **조연결**: 담보약관 각 조가 대응 보통약관 조를 안다 (UI 선택). 「생략하기」 확정 —
  (조 명 제외) 완전 동일하면 상품담보 쪽 조 생략. 준용 세부 규칙은 관통 후(P7).
- **별표는 본문 참조까지 MVP** — 별표 번호는 책자 전역, 나열 순서 = 참조 번호.
- **같은 모델링 데이터에서 다른 문서 종류(별지)가 나와야 한다** ([[범위]]) —
  저장 모델이 「약관 조문 전용」 개념에 굳으면 안 된다는 아키텍처 제약.

## 쟁점 1 — 저장 단위: 문서 노드 트리

**잠정안 (2026-08-31 제안 — 논의 필요):** 문서 = 노드 트리. 노드를 세 부류로 가른다.

| 부류 | 노드 | 비고 |
|---|---|---|
| 구조 노드 | 문서 · 조 · 항 · 호 · 목 · 표(·행) | 조는 제목(조 명)과 조연결을 가진다 |
| 블록 자리 동적 노드 | 조건 블록(if/elif/else) · 반복 블록 · 공용조항 block 참조 | 구조 노드가 서는 자리에 대신 선다 — 조 단위 on/off 가 이것 |
| 인라인 노드 | 텍스트런 · 슬롯(값 참조) · 인라인 조건 · 공용조항 inline 참조 | 문장 흐름 안에 선다 |

- **번호는 저장하지 않는다 — 계산값이다.** 조 번호·항 번호는 조건 해소 후 남은 노드에
  순서대로 매긴다. 실물 실증: 갱신형 수술비의 조 하나 추가로 이후 조 번호가 밀린다.
- 이 트리가 조립(P6)의 입력이고, 조립 결과 문서트리도 순수 데이터다 —
  산출물 스냅샷 회귀 비교([[범위]] 유예 항목)의 기반이 된다.

미결:
- [ ] **호·목 깊이의 실사용** — 알파Plus 실물에서 각 깊이의 빈도를 확인하고 노드 집합을 확정한다.
- [ ] **표의 모델** — 실물의 표는 반복(세부보장별 행)과 조건(종별 행)을 품는다.
      표 = 행 목록이고 행이 구조 노드인가, 표 전체가 리프인가. 셀 안에 인라인 노드가 서는가.
- [ ] **문서·조의 메타 항목 확정** — 문서 제목, 조 명, 조연결 외에 무엇이 더 필요한가.

## 쟁점 2 — 동적 노드의 문법과 중첩 한계

- 인라인 조건 안의 슬롯: **필수다** (「다만, 갱신형의 경우 {{값}}…」).
- 잠정안: **블록 조건의 중첩은 허용, 인라인 조건의 중첩은 금지** —
  공용조항 중첩 금지([[공용조항_기획]])와 같은 결. 현행 시스템의 실사용 확인 후 확정.
- [ ] **조건식·파생식이 식 언어를 공유하는가** — 참조 경로 + 비교 + and/or 의 한 벌로
      문면 조건과 파생([[도메인모델]] §2)을 같이 쓰면 식 = 데이터 원칙의 구현이 하나로 준다.
      잠정안: 공유. 갈리면 ADR.
- [ ] 반복 블록이 품을 수 있는 것 — 항 목록? 표 행? (구현은 P7 이나 자리는 지금 정한다)

## 쟁점 3 — 편집기의 형태와 원문 이관

- 잠정안: **구조 편집기** (조·항 블록을 단위로 추가·이동). 자유 텍스트+마크업 방식으로는
  사전평가 톤다운·부착 검사·슬롯 삽입 UI 가 성립하기 어렵다.
- [ ] **원문 이관 흐름** — MVP 실물은 보통약관 52조 + 특약 10건이다. 붙여넣기 → 조·항 구조
      자동 분해 보조가 없으면 관통 비용이 크다. P4 범위인가, 수동 입력으로 버티는가.

## 쟁점 4 — 조 번호와 상호참조

- 실물의 본문은 다른 조를 부른다 (준용규정 「보통약관 제◯조…」 등). 번호가 계산값이므로
  **텍스트로 박은 조 참조는 번호 밀림에 깨진다.**
- 잠정안: **조 참조 슬롯** — 조 id 를 참조하고 렌더 시 계산된 번호(+조 명)를 찍는다.
  같은 문서 내 참조와 보통약관 조 참조(조연결과 별개) 두 종.
- [ ] 실물에서 조 참조 표기 형태 조사 — 「제3조(보험금의 지급사유)」 형식 등 렌더 규칙 확정.
- [ ] 별표 참조(【별표13(화상 분류표)】)도 같은 방식인가 — 별표 번호는 책자 전역 계산값이다.

## 쟁점 5 — 사전평가의 값 출처

- 담보약관 편집 문맥에서 담보 레벨 조건은 평가 가능 ([[도메인모델]] §3). 그 값은
  **담보 마스터에 입력된 값**이다 — 탑재 스냅샷이 아니다.
- 긴장: 분기의 존재 이유가 탑재분 간 값 차이인데(갱신형/비갱신형), 마스터 값 하나로
  사전평가하면 그 분기는 늘 한쪽만 산다. 전체 뷰 토글이 이를 보완하지만—
- [ ] **가상 문맥 시뮬레이션이 필요한가** — 편집 화면에서 값을 임시로 바꿔 보며 분기를
      확인하는 기능. MVP 인가, 전체 뷰 토글로 충분한가.

## 쟁점 6 — 보통약관 마스터 관리와 조연결 최소형

- 모델은 보통약관 마스터 N 벌 · 상품이 선택. MVP 관통은 알파Plus 1벌이면 된다 —
  화면은 목록 + 선택의 최소형.
- 조연결 최소형 = 담보약관의 각 조에 대응 보통약관 조를 고르는 UI 까지.
  조합 옵션 정의(보통약관 조에 두는)·준용 문구 자동 생성은 P7 준용 기획으로.
- [ ] **「생략하기」의 판정 주체** — (조 명 제외) 완전 동일의 비교를 조립이 자동으로 하는가,
      편집자가 명시 플래그로 켜는가. 동일 여부가 조건 해소 후에야 확정되는 점 주의.

## 경계 (P4 가 만들지 않는 것)

- 준용 규칙 세부 (P7) — 조연결은 「대응 조 선택 + 생략하기」까지.
- 반복문·표 구현 (P7 관통 2) — 단, 저장 모델의 자리는 쟁점 1·2 에서 지금 확보한다.
- 종별 문구 메커니즘 (P7) — 세목 존재 조건 + 종형명 치환. 저장 모델이 배제하지 않게만 유지.
- 파생 구분자 식 편집 (P7).
- 표지·목차·`.docx` ([[범위]]).
