# 상품탑재 기획

> 상태: 합의 · 최종수정: 2026-08-31
> 대응 도메인모델: [[도메인모델]] §1 실체 뼈대 · 개발 단계: [[개발순서]] P5

## 해결하려는 것

상품모델링 — 상품을 만들고, 세목을 구성하고, 담보를 탑재해 상품담보를 만들고,
기본계약을 지정하는 동작을 정한다. **상품담보가 특별약관 한 벌이 나오는 단위**이므로
「상품담보가 무엇으로 결정되는가」가 이 기획의 본체다.

## 확정된 전제 (도메인모델·기존 기획에서)

- 탑재는 값 스냅샷 ([[ADR-0002-탑재-값스냅샷]]) — 필드 단위 수정, 이후 마스터 변경 무영향.
- 세목: 종·형 축 + 유형 구조체, 조합은 카테시안이 아니라 **명시 등록** ([[ADR-0006-세목-축모델]]).
- 고지유형은 세목이 아니라 상품 레벨 enum 구분자.
- 기본계약 = 상품담보 중 정확히 1개 지정 (MVP — [[범위]]). 지정 순간 보통약관의
  부착 검사가 돈다 ([[ADR-0011-보통약관문맥-기본계약]]).
- 상품 레벨 구분자 값 입력은 P1 폼 렌더러 재사용.

## 담보속성 (2026-08-31 확정 → [[ADR-0015-담보속성-복원]])

도메인모델의 「별도 장치 없이 값 차이가 곧 탑재분의 구별」을 **번복**하고,
**담보속성을 별도 카탈로그 실체로 복원**한다.

- **카탈로그** — 담보속성은 **종류**(예: 갱신유형·부가유형)와 종류별 **유효값** 목록으로
  구성되고, 종류·유효값 모두 **유저가 수정 가능한 데이터**다 (코드 아님).
- **상품담보 = 담보 × 담보속성 값 조합.** 이 조합으로 상품담보가 하나 결정된다 —
  같은 조합의 중복 탑재는 서버가 거부한다 (유일성).
- **필요한 속성만 붙인다 (sparse).** 모든 속성 종류를 강제 선택하지 않는다.
  새 속성 종류를 채번하면 그 이후에 만드는 상품담보의 형태가 달라질 뿐,
  기존 상품담보는 그 속성 「미사용」으로 남는다.
- **식의 참조 대상이다.** LHS 가 담보속성이면 연산은 세 가지뿐 —
  `exist(속성종류)` (사용 여부) · `속성종류 = 값` · `속성종류 ≠ 값`.
  **RHS 는 그 속성의 유효값 리터럴만** 허용한다 (구분자 참조 불가).
- **작성은 관대, 평가는 엄격** — exist 가드 없이 `갱신유형 = 갱신형` 을 써도 되지만,
  평가 시점에 그 상품담보가 해당 속성을 안 쓰고 있으면 **오류 + 좌표 보고**다.
  조용히 false 로 넘어가지 않는다 (미입력 참조와 같은 결 — [[ADR-0004-null없음-미입력상태]]).
  미사용 담보에서 분기를 건너뛰려면 작성자가 명시적으로 `exist(…) and …` 를 쓴다.
- **작명의 재료다.** default 상품담보명은 담보속성 조합에서 생성하고,
  **속성별 담보명 규칙(prefix/suffix 류)도 유저 정의 데이터**다. 생성 후 수동 변경 가능.
  (도메인모델의 「파생 축 구분자의 작명 메타」는 담보속성 정의로 이동 — 구분자에서는 폐기.)
- **담보약관 편집 문맥에서 담보속성 조건은 미결이다** — 속성은 탑재 때 정해지므로
  마스터에 값이 없다. 상품 레벨 조건과 같이 미결 표시하고, 전체 뷰·상품담보 미리보기
  ([[문면_기획]])로 확인한다.
- 변경·삭제 규칙은 [[구분자_기획]] 의 MVP 잠정 규칙을 준용한다 —
  사용 중(상품담보·식이 참조) 삭제는 프로덕션 서버 거부, 유효값 표시명 변경은 자유.

## 세목 — 명시 등록이 곧 제약 (2026-08-31 확정)

- 유효 조합은 명시 등록으로 확정돼 있다. 여기에 **제약 엔진을 얹지 않는다** —
  「특정 고지유형에서는 기본납입형만」 같은 제약은 사람이 유효한 조합만 등록하는 것으로
  표현된다. 등록 실수는 관계정보 뷰·미리보기로 잡는다. 전상품 확대 때 재판단.
- **상품담보마다 부착되는 세목(적용 조합)이 다르다 — 유저가 상품담보별로 설정한다.**
  기본값·화면 흐름은 [[02_UI]] 화면기획에서.

## 문서 산출 (2026-08-31 확정)

- **상품담보 하나 = 특약 문서 한 벌.** 등록된 담보속성 조합별로 담보약관이 파생·산출된다.
- **문면 없는 담보를 허용한다** — 담보 마스터가 문면을 갖지 않으면 그 탑재분은
  조립에서 문서를 내지 않는다 (모델의 성질).
- 현행 시스템의 특별조건부 담보는 별지·PV 산출 때문에 필요한 것이다.
  **이 프로젝트는 약관 전용이므로 MVP 에서는 특별조건부 담보속성을 만들지 않는다** —
  별지 단계([[범위]] 향후)에서 다시 판단한다.
