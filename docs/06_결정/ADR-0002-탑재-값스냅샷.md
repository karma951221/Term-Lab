# ADR-0002 — 탑재는 값 스냅샷이다

> 상태: 채택 · 날짜: 2026-08-29

## 맥락

담보는 재사용 마스터인데 감액·면책 같은 값은 상품마다 다르다. 같은 담보를 쓰는 상품들이
값을 공유하면 안 되는 상황을 어떻게 감당할지가 문제였다. 검토한 갈래:

- 상품마다 값이 다르면 다른 담보로 채번 (담보 = 값까지 동일한 단위)
- 담보를 상품별로 복제해 운영
- 담보를 아예 상품의 자식으로 (마스터 폐지)
- 오버라이드 레이어 — 마스터 값 위에 상품담보가 덮어쓰기 (terms-lab 방식: 해소 순서
  「구체적 오버라이드 > 마스터 값 > 기본값」을 읽을 때마다 계산)

## 결정

**탑재 시점 값 스냅샷.** 담보를 상품에 탑재하는 순간 마스터 값이 상품담보로 복사되고,
이후 마스터 값 변경은 이미 탑재된 상품담보에 영향을 주지 않는다(이후 탑재분에만).
수정은 **필드 단위**. 공유되는 것은 **구조(트리)뿐** — 구조는 마스터 소유이고 상품담보는
구조를 빼거나 바꿀 수 없다(값만 다르다, 2026-08-29 확인).

## 이유

- 값 해소가 단순하다 — 탑재 후엔 상품담보의 값이 그냥 정답. 읽을 때 마스터를 거슬러
  올라가는 계산이 없다.
- 값의 출처가 하나로 유지된다(S3) — 구분자 정의는 마스터에 하나, 스냅샷은 그 정의의 값 행일 뿐.
- 실무 감각과 일치 — 마스터를 고쳤다고 이미 판매 설계된 상품의 값이 바뀌면 그게 사고다.

## 버린 대안

- **라이브 오버라이드(terms-lab 방식)** — 마스터 수정이 기존 상품에 흘러드는 것 자체가
  약관에서는 위험. 값 해소도 복잡.
- **담보 복제 운영** — 중복 채번 문제의 재생산.

## 결과와 감수하는 비용

- 마스터 값의 일괄 개정이 자동 전파되지 않는다 — 필요하면 그때 도구를 만든다.
- 구조는 살아있는 공유라 경계 문제가 생긴다 → 구조 변경은 프로덕션 금지·개발 허용
  (ADR 별도 아님, [[도메인모델]] §5), 개발 모드에서 추가 노드는 빈 값·삭제 노드 값 행 연쇄 삭제
  (2026-08-30 채택 — 「추가 시점 마스터 기본값 복사」는 탑재 외 두 번째 복사 시점을 만들어 기각).
