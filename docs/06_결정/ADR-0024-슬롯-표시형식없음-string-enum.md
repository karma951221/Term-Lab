# ADR-0024 — 값 슬롯은 string · enum 만 · 표시 형식 규칙은 만들지 않는다

> 상태: 채택 · 날짜: 2026-09-06

## 맥락

number 값이 문면에 「2.50%」·「1,000만원」처럼 찍히려면 표시 형식(단위·소수 자리·천 단위)을
누군가 정해야 한다 — 필드 정의에 두나, 슬롯에 두나, 둘 다인가가 [[도메인모델]] §7 미결이었다.

## 결정

1. **표시 형식 규칙은 만들지 않는다.** 문면에 찍을 값은 처음부터 **string** 으로 정의한다
   (「2.5%」는 string 값이다). number 는 식(비교·집계) 전용이다. 같은 값을 문면에도 찍고 식에서도
   쓰면 string 필드와 number 필드를 따로 둔다.
2. **값 슬롯이 받는 타입은 string 과 enum 뿐이다.** enum 은 표시명으로 찍힌다(코드는 저장·식 전용).
   number · boolean · date · list<enum> 슬롯은 편집기가 거부한다.

## 이유

- 형식 속성은 오버엔지니어링이다 — string 으로 적으면 끝나는 문제에 정의·UI·변환기가 붙는다.
- 「이상하게 찍히는 경로」(`2.5` · `2026-01-01` · `true`)를 남기지 않는다. 형식 차이가 리터럴 비교
  (생략 판정)를 깨는 원인이 되는 것도 막는다.

## 버린 대안

- **A. 필드 정의에 표시 형식** — 일관되지만 정의 항목이 늘고 변환기가 필요. 기각.
- **B. 슬롯에 표시 형식** — 같은 값이 자리마다 다르게 찍혀 생략 판정을 흔든다. 기각.
- **막지 않고 toString** — 이상한 출력 경로가 남는다. 기각.

## 결과와 감수하는 비용

- 문면용 string 과 식용 number 가 **두 필드**로 중복되는 구분자가 생긴다. 두 값의 일치는 사람이
  지킨다 (도구가 검증하지 않는다).
- 슬롯 삽입 UI 가 타입으로 후보를 거른다.
