# ADR-0029 — 실물 재현 노드 확장: 관 · 정적 표 · 박스, 가지번호 없음

> 상태: 채택 · 날짜: 2026-09-07

## 맥락

알파Plus 실물 보통약관은 관(款) 7개 · 표 ~20개 · 【용어풀이】 박스 다수 · 가지번호 조 4개를 갖는다.
문면 모델(ADR-0012)에는 관·표·박스 노드가 없고, 표는 「동적 표」로 묶여 MVP 이후로 유예돼 있었다.
2026-09-07 유저 결정: 조항호목 텍스트뿐 아니라 **정적 표와 박스까지 재현**하고, 표는 유저가 편집기에서 직접 입력하며
제목줄 서식·열 너비까지 저장한다.

## 결정

- 노드 3종을 추가한다 — `section`(관: 제목 + 조 목록) · `table`(제목? · 열 너비 · 행 = 제목줄 여부 + 셀 텍스트) · `box`(제목 + 줄 목록).
  표·박스는 항·호·목 **뒤에 붙는 번호 없는 블록**이다. 허용 자식 규칙의 확장이며 저장 구조는 그대로다.
- 표 서식은 **제목줄 여부와 열 너비(%)** 두 가지뿐이고 노드 필드로 트리 jsonb 에 저장된다.
- **가지번호(제N조의M)는 두지 않는다.** 실물의 가지번호 조는 순번으로 다시 매긴다. 참조는 슬롯이라 함께 따라간다.
- 항이 정확히 하나인 조는 항 마커를 찍지 않는다 (실물의 단항 조는 전부 번호 없음).
- 준용 판정(ADR-0020)의 비교 단위에 표·박스를 각각 한 단위로 넣는다.

## 이유

- 「동일한 약관」이 목표다 — 표·박스를 빼면 본문만 같은 반쪽 재현이다.
- 정적 표는 동적 표(반복·조건 행)와 분리 가능하다. 동적 표는 여전히 유예하고, 정적 표 노드가 그 자리를 미리 차지한다.
- 가지번호는 개정으로 조를 끼워 넣을 때 생기는 표기다. 이력·개정은 MVP 이후(ADR-0026)라 지금 표기 규칙을 만들면 근거 없는 메타가 된다.

## 버린 대안

- 표·박스 자리만 플레이스홀더로 표시 — 내용이 없어 대조가 안 된다.
- 조 메타 `branch: true` 로 가지번호 계산 — 「조의 메타는 조 명·조연결뿐」 규칙의 예외를 개정 기획 없이 만든다. 기각.
- 표 서식을 CSS 클래스명 문자열로 저장 — 화면에 종속된다. 의미(제목줄·너비)만 저장.

## 결과와 감수하는 비용

- 실물 대조에서 조 번호는 순서로만 맞는다 — 실물 `제27조의1` 이 `제28조` 로 나온다. 대조기는 조 명 기준으로 참조를 정규화한다.
- 편집기·렌더·준용 비교·변환 스크립트가 노드 3종을 안다. 동적 표 기획 때 `table` 을 확장한다(행 반복·조건 행).
