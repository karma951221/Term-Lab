# ADR-0007 — 파생식은 데이터 · 집계 범위 = 부착점의 하위 트리

> 상태: 채택 · 날짜: 2026-08-29

## 맥락

사내 시스템에서 파생 로직(`보험금지급.면책여부 = any(급부1면책여부, 급부2면책여부, …)`)은
구분자마다 **개발자에게 요청해 코드에 심는** 방식이었다. 결과: 로직이 블랙박스에 갇혀
기획자가 식을 다시 볼 수 없고, 구분자 수만큼 손코드가 쌓여 버그·중복의 원천이 됐다.
또 기존 시스템은 순회가 **「담보의 모든 세부보장」으로 고정**되어 세부보장 단위 조건식이
불가능했고, 담보별 예외처리가 폭발했다.

## 결정

- **파생식은 데이터다.** 구분자 정의에 식이 저장되고 화면에서 읽힌다.
  새 파생 구분자를 만드는 데 개발 요청이 필요 없다 ([[문제정의]] S4).
- 집계 연산 6종: `any` · `all` · `sum` · `count(distinct)` · `exist` · `not exist`.
  (exist/not exist 는 종별 문구 유즈케이스의 「세목 존재 조건」에도 쓰인다.)
- **집계 범위 = 부착한 실체의 하위 트리.** 별도 범위 지정 문법을 두지 않는다 —
  세부보장에 부착한 파생은 자기 급부들을, 담보에 부착한 파생은 자기 아래 전체를 훑는다.
  「어디 붙였나」가 곧 「무엇을 훑나」. **세부보장 단위 순회·조건식 지원이 기존 시스템 대비
  핵심 개선.**
- 형제·타 담보를 읽는 식은 사내에서도 알려진 사례가 없다(2026-08-29 확인) —
  필요해지면 그때 참조 문법을 연다.
- 다단 파생(파생이 파생을 읽음)은 MVP 제외.
- 문면 반복문(`for 세부보장 in 세부보장목록`)도 같은 순회 메커니즘의 문면 쪽 얼굴이다 —
  순회 소스가 값이 아니라 **모델링 구조**라서, terms-lab 이 막혔던 「반복문 입력 경로가
  시드뿐」 문제가 소멸한다. (반복문 MVP 제외 결정은 2026-08-30 번복 — 수술비 담보의
  보장범위 나열·지급금액표 행이 반복 없이 성립하지 않음.)
