# ADR-0009 — 테스트 분담: Vitest 스냅샷 위주 + Playwright 소수 정예

> 상태: 채택 · 날짜: 2026-08-30

## 맥락

의뢰인 질문: "Playwright 가 아니라 Vitest 쓰는 이유 있어?" — 대체재가 아니라 층이 다르다.

## 결정

| 검증 대상 | 도구 | 비중 |
|---|---|---|
| 조립·조건 평가·파생·번호 계산 (문서트리 스냅샷) | Vitest | 대부분 |
| 에디터·폼 렌더러 등 핵심 화면 흐름 | Playwright E2E | 소수 정예 |

## 이유

- 이 프로젝트의 핵심 로직은 전부 **순수 데이터 변환**이고 중간 산출물 문서트리가 순수
  데이터라서, 브라우저 없이 스냅샷 비교로 밀리초 단위 회귀가 가능하다.
- 조립 검증을 E2E 로 하면 느리고, 「조립이 틀렸다」와 「화면이 깨졌다」의 원인이 섞인다 —
  이 분리는 src/domain 순수층(ESLint import 차단)으로 구조에도 박혀 있다.
- MVP 인수는 원문 diff 자동화가 아니라 눈 검증 (2026-08-30 의뢰인 — diff 불요).
  대신 MVP 후 「시점 스냅샷 vs 재산출 비교」 회귀 기능의 기반이 문서트리다.
