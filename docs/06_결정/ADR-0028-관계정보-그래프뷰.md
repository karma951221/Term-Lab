# ADR-0028 — 관계정보 그래프 뷰: 결정적 동심원 배치 · 종류는 모양+색 이중부호화

> 상태: 제안 · 날짜: 2026-09-07

## 맥락

참조는 이미 그래프다 (`src/domain/refs/`). 노드 16종·간선 15종이 DB 전체에서 만들어지고,
관계정보 화면([[화면/관계정보_화면기획]])이 정·역방향을 **목록**으로 보여준다.

목록은 좌표를 정확히 주지만 모양을 주지 않는다. 「이 구분자를 고치면 어디까지 번지나」는
목록을 여러 번 타고 들어가야 보인다. 그림으로 보면 한 번에 보인다.

그런데 그림에는 두 가지가 걸린다.

1. **디자인원칙 §1.3** — 색은 강조(`mark`)와 현재 위치만 가리킨다. 브랜드 컬러를 두지 않고,
   semantic 4색은 흙빛으로 묶었다. 「객체 유형을 색으로」는 이 원칙과 정면으로 부딪힌다.
2. **의존성** — 지금 런타임 의존성은 next · react · drizzle · pglite · zod 다섯뿐이다.
   d3-force · cytoscape · reactflow 는 전부 무거운 클라이언트 라이브러리다.

## 결정

1. **이웃 그래프만 그린다.** 조회 대상을 중심에 둔 N홉 부분그래프. 전체 지도는 만들지 않는다.
   상한은 노드 300 · 간선 600이고, 넘으면 **부분을 그리지 않고 거절한다** — 잘린 그림은 거짓 안심을 준다.
2. **배치는 결정적 동심원.** 힘 시뮬레이션을 쓰지 않는다. 링 k = k홉 노드, 링 안에서는
   (종류 → `nodeKey`) 순으로 각도 균등 배분, 링 반지름은 노드 수에 따라 벌어진다.
3. **렌더는 서버가 좌표까지 계산한 인라인 SVG.** 새 의존성 0. 클라이언트 JS 는 줌·팬·호버 강조만.
4. **종류는 「모양 + 테두리 색」 이중 부호화.** 모양 3종(원 정의류 · 사각 문면류 · 마름모 모델링류)이
   1차 채널이고, 종류 색(`--ts-graph-*`, 채도 낮춘 흙빛 8색)은 2차 채널이다.
   **색만으로 구별되는 것이 없다.**
5. **`mark` 와 `error` 는 종류 색에 쓰지 않는다.** 그래프 안에서 `mark` = 현재 조회 대상(§1.3 「현재 위치」),
   `error` = 깨진 참조뿐이다.
6. **간선 형태(15종)는 색이 아니라 선 스타일 3묶음**(본문 참조 실선 · 구조 결합 파선 · 비참조 점선).
7. **포함 관계(`parent`)를 화살표 없는 가는 선으로 함께 그린다.** 참조 간선만 그리면 「문서 ↔ 그 문서의 조」가
   끊어져 조 노드가 떠 버린다. 포함 선은 홉을 만들지 않는다.

## 이유

- **결정적 배치가 힘 시뮬레이션을 이긴다** — 목적이 「바꾸기 직전 확인」이라 *어제 본 그림과 오늘 본 그림이
  같아야* 한다. force 는 열 때마다 다른 그림을 준다. 덤으로 스냅샷 테스트가 가능하고, 서버에서 계산되며,
  JS 없이도 그림이 나온다.
- **§1.3 은 「색으로만 말하지 마라」이지 「색을 쓰지 마라」가 아니다.** 그래프에는 위치·크기·글자 말고
  쓸 채널이 적어서 모양과 색을 같이 쓴다. 모양이 1차 채널이면 §1.2(「상태는 형태가 말한다」)와
  §10 Q1(mark↔error 대비 부족)의 위험을 피한다.
- **의존성 0** — 노드 300 상한 안에서는 SVG 로 충분하다. 라이브러리 하나가 번들과 다크 테마와
  접근성 전부에 손을 댄다.

## 버린 대안

| 대안 | 버린 이유 |
|---|---|
| **d3-force / cytoscape / reactflow 도입** | 의존성 하나에 번들·테마·접근성이 딸려 온다. 노드 300 상한에서 얻는 게 적다. 무엇보다 매번 다른 그림이 나온다 |
| **전체 그래프 한 판 (옵시디언 global graph)** | 수천 노드는 읽히지 않고, 「영향 반경」에 답하지 않는다. 예뻐 보이는 것 말고 얻는 게 없다 |
| **노드를 실체 단위로 뭉치기** (조·필드를 부모에 접기) | 읽기는 편하지만 `RefGraph` 와 1:1이 아닌 변환층이 생긴다. 변환층은 조용히 틀린다 — 영향 반경을 보러 온 화면에서 가장 나쁜 실패다. 읽힘은 홉 제한과 필터가 맡는다 |
| **간선 형태 15종을 15색으로** | 색 수프. §1.3 위반이고 다크에서 구별이 무너진다 |
| **계층(DAG) 배치** | 참조 그래프에 순환이 있다 (`cycles()` 가 그걸 찾는 함수다). 계층 배치는 순환에서 무너진다 |

## 결과와 감수하는 비용

- **감수:** 동심원은 간선 교차를 최소화하지 않는다. 링 위 노드가 많으면 선이 지저분해진다 —
  필터와 깊이로 줄이는 게 답이고, 자동으로 예뻐지지는 않는다.
- **감수:** 노드를 손으로 못 옮긴다. 겹친 라벨은 호버·tooltip 으로 읽는다.
- **감수:** 색 토큰이 8개 늘어난다 (`--ts-graph-*` · 라이트/다크). 이 색들은 **그래프 안에서만** 쓴다 —
  다른 화면으로 새어 나가면 §1.3 이 무너진다. 코드 리뷰에서 막는다.
- **얻음:** 새 의존성 0, JS 없이도 보이는 그림, 픽셀 단위 회귀 테스트, 늘 같은 배치.
