# ADR-0001 — 폼 전체가 구분자 하나다 (구조체 = 타입)

> 상태: 채택 · 날짜: 2026-08-29

## 맥락

"모든 입력 폼은 구조체, 입력값은 전부 구분자 값" 전제에서, 이 두 문장을 잇는 방법이 둘 있었다.

- **A. 구조체 = 구분자들의 묶음** — 필드 하나하나가 독립 구분자, 구조체는 폼 배치 정의.
  채번 단위 = 필드. 조건식은 구분자를 직접 참조(`면책여부`).
- **B. 구조체 = 타입** — 폼 전체가 구분자 하나, 값은 객체 하나. 채번 단위 = 폼.
  조건식은 경로 참조(`보험금지급.면책여부`).

## 결정

**B.** 폼 전체가 구분자 하나이고 구조체는 그 타입이다. 필드는 구조체가 직접 소유한다.

## 이유

- 의뢰인이 문제정의 단계에서 이미 B 를 가리켰다 — "기존이라면 flat 한 구분자들을 여러 개
  채번했겠지만, 이제는 하나만 채번하면 되잖아." 채번 수 감소가 이 프로젝트의 기대 효과다.
- 사내 시스템의 실제 파생식 예시(`보험금지급.면책여부 = any(…)`)가 점(.) 경로 표기였다 —
  현장의 머릿속 모델이 이미 경로다.

## 버린 대안

- **A** — 채번 단위가 필드라 구분자 수가 줄지 않는다. 기대 효과와 정면 충돌.
- **B + 필드 사전 절충안** — 필드가 공용 "필드 사전"(개념 등록처)을 참조하게 해서
  필드 레벨 중복 채번(`보험금지급.면책여부` vs `지급제한.면책여부`)을 막고, 파생 집계가
  구조체와 무관하게 사전 개념 기준으로 순회하게 하는 안. 클로드가 제안했으나
  **의뢰인이 오버엔지니어링으로 판단, 기각** (2026-08-29).

## 결과와 감수하는 비용

- 같은 개념의 필드가 서로 다른 구조체에 중복 생성되는 것을 시스템이 못 막는다.
  **[[문제정의]] S2(중복 채번 방지)의 시스템 보증 범위가 구분자(폼) 단위로 좁아진다** —
  필드 단위 중복은 운영 리뷰로 잡는다. 실제로 아파지면 그때 장치를 단다.
