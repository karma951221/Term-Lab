# ADR-0025 — 작명 규칙: 유효값별 명칭 조각 표 + 카탈로그 전역 칩 템플릿

> 상태: 채택 · 날짜: 2026-09-06

## 맥락

[[ADR-0015-담보속성-복원]] 은 「담보속성별 담보명 규칙(prefix/suffix)·조합 적용 순서」를 유저 정의
데이터로 두되 문법은 미뤘다. 2차 구현(2026-09-04)은 잠정 문법 — 유효값에 `{prefix, suffix}`, 종류의
전역 order 로 나열, 토큰 사이 공백 1칸 자동 — 으로 `src/domain/product/naming.ts` 를 만들었다.
2026-09-06 기획에서 공백을 작성자가 표현해야 하고(「갱신형 [담보명]」), 순서도 작성자가 정해야
한다는 요구가 나왔다.

## 결정

1. **명칭 조각 표** — 담보속성 종류 × 유효값 → 조각 문자열 하나 (예: 갱신유형/갱신형 → 「갱신형」,
   부가유형/추가 → 「추가」, 비갱신형 → 빈칸). prefix/suffix 구분은 없다 — 자리는 템플릿이 정한다.
2. **담보명 템플릿은 카탈로그 전역 하나** — 칩을 순서대로 놓은 한 줄. 칩 = 담보속성 종류 또는
   `[담보명]`. 칩 사이 공백·문자는 작성자가 친 그대로. 예: `[특별조건부] [갱신유형] [담보명] [부가유형]`.
3. **치환** — 칩은 그 상품담보가 선택한 유효값의 조각으로 바뀐다. 미사용 속성·빈 조각·템플릿에 없는
   속성은 빈 문자열. 결과는 연속 공백을 1칸으로, 앞뒤 공백을 정리한다.
4. 생성된 이름은 default 상품담보명이며 수동 변경 가능(ADR-0015 그대로). 「Ⅱ」·「보장」 같은 것은
   담보명의 일부다 — 속성이 아니다.

## 이유

- 공백을 자동으로 넣으면 「골절수술비Ⅱ보장」류 붙여쓰기와 「일반상해사망보장 추가」 띄어쓰기를 한 규칙으로
  못 담는다. 작성자가 치는 것이 정확하다.
- 순서는 회사 규정이라 담보별로 다를 이유가 없다 — 전역 하나가 순서 불일치를 막는다.

## 버린 대안

- **현행 잠정 문법 유지** (prefix/suffix + order 나열 + 공백 1칸) — 기각: 공백·순서를 작성자가 못 정한다.
- **유효값별 템플릿** 「갱신형 [담보명]」을 값마다 두고 order 로 겹싸기 — 기각: 겹싸는 방향(안/바깥)을
  따로 정해야 하고, 순서가 속성 order 에 묶여 이름 규칙과 정렬 규칙이 섞인다.
- **담보별 템플릿** — 기각: 순서 불일치.

## 결과와 감수하는 비용

- `naming.ts` 의 `{prefix, suffix}` 와 공백 1칸 결합을 조각 표 + 템플릿으로 바꾼다. 담보속성 종류의
  전역 `order` 는 **정렬(그룹 안 2차 키)에만** 남고 작명에서는 쓰지 않는다.
- 담보속성 종류를 새로 만들면 템플릿에 칩을 넣어야 이름에 반영된다 — 빠뜨리면 이름에 조용히 안 나온다.
  담보속성 카탈로그 화면이 「템플릿에 없는 종류」를 표시해 준다.
