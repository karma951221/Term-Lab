# ADR-0023 — 참조 슬롯: 다중 대상 덩어리 · 조·항·호·목 전부 · 실물 렌더 표기

> 상태: 채택 · 날짜: 2026-09-06

## 맥락

[[01_기획/문면_기획]] 은 조·별표 참조 슬롯의 렌더 표기를 「실물 조사 후 확정」으로 열어 뒀다.
2026-09-06 실물(알파Plus 특약 10건 + 보통약관 52조)을 조사해 두 가지가 드러났다 —
① 나열에서 접두 「보통약관」은 첫 항목에만 붙는다 (「보통약관 제9조(…), 제10조(…) 및 제38조(…)」),
그런데 같은 문장 안에서도 다른 나열이 시작되면 다시 붙는다. ② 같은 조 안 「제1항」·「제2항」 참조가
31건 있다 — 항 번호도 계산값이라 조건으로 항이 빠지면 텍스트로 박힌 번호는 조용히 틀린다.

## 결정

1. **참조 슬롯은 대상을 여러 개 가질 수 있다** (다중 참조 = 덩어리 하나). 접두 「보통약관 」은
   덩어리당 한 번, 안의 대상은 쉼표로 나열하고 마지막 앞에만 **연결어**를 넣는다. 연결어는 슬롯
   속성(자유 입력, 기본 「및」). 편집 UI 에 렌더 미리보기를 둔다.
2. **참조 대상은 조·항·호·목 전부**다. MVP 포함. 렌더는 실물 형식을 따른다 →
   [[01_기획/문면_기획]] §참조 슬롯.
3. 별표 참조는 단일 대상, `【별표N(별표명)】`.

## 이유

- 접두 생략을 텍스트(문장·접속어)로 판정하는 안은 「같은 문장」이 실물과 맞지 않고 노드 트리에
  문장 경계가 없어 기준이 흔들린다. 작성자가 덩어리를 만들면 판정할 것이 없다.
- 항·호·목도 번호가 계산값이다. 「조용히 틀린 문서를 남기지 않는다」(문면_기획 참조 무결성)는
  조에만 적용할 이유가 없다.

## 버린 대안

- **A. 슬롯마다 「접두 표시」 체크** — 작성자가 나열 두 번째부터 끈다. 기각: 덩어리 모델이 더 단순.
- **B'. 인접 슬롯 사이 텍스트가 접속어뿐이면 자동 생략** — 기각: 접속어 목록·공백 규칙이 늘고
  인라인 조건이 끼면 판정이 불투명.
- **C. 항상 접두** — 실물과 다르다. 기각.
- **항 참조를 MVP 이후로** — 관통 1 픽스처는 당장 안 틀리지만 원칙 위반. 기각.

## 결과와 감수하는 비용

- 노드 종류 `articleRef` 가 「대상 목록 + 연결어」를 갖는 다중 참조로 바뀌고, 대상 종류에 항·호·목이
  들어간다 (설계·구현 갱신). 「대상이 분기로 사라짐」 오류는 대상 단위로 보고한다.
- 참조 UI 가 조 선택기에서 트리 선택기(조 › 항 › 호 › 목)로 커진다.
