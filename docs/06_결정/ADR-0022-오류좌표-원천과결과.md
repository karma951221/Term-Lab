# ADR-0022 — 오류 좌표: id 키 + 렌더 표시 · 원천과 결과 자리를 함께 담는다

> 상태: 채택 · 날짜: 2026-09-06

## 맥락

[[ADR-0016-조립-부분조립-오류좌표]] 가 「좌표 + 클릭 이동」을 확정했지만 형식은 없었다. 좌표는 사람이
읽는 문자열이면서 이동 키이고, 조·항 번호는 계산값이라 상품마다 다르다. 또 오류는 조립 결과에서
발견되지만 고치는 곳은 원천(마스터 문면 노드 · 값 입력 칸)이다.

## 결정

1. **키와 표시를 분리한다.** 내부 키는 노드 id 경로(불변), 표시는 조립 결과로 렌더한 문자열.
2. **좌표는 원천과 결과 자리를 함께 담는다.** 패널 동작은 「미리보기에서 보기」·「고치러 가기」 둘.
   원천이 여럿이면 첫 번째만.
3. 오류 종류별 원천 화면·표시 문자열 규칙은 [[01_기획/오류좌표_기획]] 에.

## 이유

- 표시 문자열을 키로 쓰면 같은 자리가 상품마다 다른 이름을 갖는다 (번호가 계산값).
- 미입력은 값 화면으로, 깨진 참조는 문면 편집기로 가야 한다 — 원천 종류가 오류마다 다르고,
  결과 자리도 봐야 문맥을 안다. 둘 다 필요하다.

## 버린 대안

- **A. 표시 문자열이 곧 키** — 단순하나 번호가 바뀌면 좌표가 바뀐다. 기각.
- **B. 결과 자리만** — 미리보기 스크롤만 하고 원천 찾기는 사람 몫. 기각: 수정 사이클이 길어진다.
- **C. 원천만** — 결과 문맥을 못 본다. 기각.
- **원천 여럿을 전부 보여주기** — 패널이 복잡해지고 실익이 적다. 첫 번째만.

## 결과와 감수하는 비용

- `Coordinate` 에 원천/결과 구분과 절·블록 이름공간이 들어간다 (설계 갱신).
- 원천이 여럿인 오류에서 두 번째 이후 원천은 사람이 알아서 찾아야 한다.
