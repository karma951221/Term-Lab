# 유형 화면기획

> 상태: 초안 · 최종수정: 2026-09-06
>
> 대응 기획: [[01_기획/구분자_기획]] · 대응 액션: [[02_UI/유저액션/구분자_액션]] §구조체 필드 · §enum 유효값 · 레이아웃: [[02_UI/디자인원칙]] §2 L1 · L2

구분자가 **고르거나 담는 것**을 관리하는 탭. 2026-09-06 에 구분자 탭에서 떼어 냈다 —
「enum 목록」 버튼이 조회 화면 툴바에 얹혀 있던 것을 없애고([[구분자_화면기획]] Q-A), 선택지와 구조체를
한 탭에 모은다. 구분자 탭은 「무엇을 묻나」, 유형 탭은 「어떤 모양의 값으로 답하나」다.

| 하위 탭 | 도메인 | 현업 이름 (화면 라벨) | 관리하는 것 |
|---|---|---|---|
| 선택지 | enum 정의 · 유효값 | **선택지** (「enum」 은 화면에 안 쓴다) | 선택형 구분자 · 필드가 고르는 값 목록 |
| 폼 | 구조체 타입 구분자 · 필드 | **폼** (「구조체」 는 화면에 안 쓴다 — 2026-09-06 확정) | 폼 하나 = 구조체 하나. 필드의 추가 · 순서 · 타입 |

탭 「유형」 · 하위 탭 「선택지 · 폼」 (2026-09-06 확정, Q-A). 좌측 내비 순서는 「구분자」 바로 다음.
「폼」 은 화면의 입력 양식이라는 일반 뜻과 겹치므로 제목 · 빈 상태 문구에서 「값 여러 개를 한 번에 묻는 폼」 으로 한 번 풀어 준다.
문서 · 코드의 도메인 용어는 그대로 「구조체」 다.

**폼(구조체)은 여전히 구분자다.** [[06_결정/ADR-0001-폼구조체-구분자하나]] — 폼 하나 = 구조체 타입 구분자 하나.
이 탭이 폼을 따로 보여 주는 것은 **필드 편집의 정본 자리**를 옮기는 것이지 도메인을 쪼개는 것이 아니다.
구분자 탭 조회에는 종류 = 폼으로 계속 잡히고, 구분자 상세는 필드를 읽기만 하며 「폼 탭에서 편집」 링크를 둔다.
도메인을 쪼개는 안(구조체 정의와 그것을 쓰는 구분자를 분리)은 Q-D.

## 1. 선택지 조회 (`/types/enums`)

### 목적

선택지 목록을 훑고, 하나를 골라 값을 손본다. 값을 늘리는 일은 코드 배포 없이 여기서 끝난다
([[06_결정/ADR-0005-코드-표시명-이중체계]]).

### 화면 구성

```
┌──────────────────────────────────────────────────────────┐
│ 유형   [선택지] 폼                                   [+]   │  하위 탭 + 「새 선택지」
├──────────────────────────────────────────────────────────┤
│ 🔍 코드 · 표시명 · 값        기준일 [2026-09-06] □미확정 포함│  sticky
│ 사용처: 있음 ✕                                             │  칩 줄 (없으면 안 그림)
├──────┬────────────────┬──────────────────────┬────┬───────┤
│ 코드 │ 표시명          │ 값                    │ 수 │ 사용처 ▾│
├──────┴────────────────┴──────────────────────┴────┴───────┤
│ 총 N건                                       (여러 페이지) ‹ ›│
└──────────────────────────────────────────────────────────┘
```

- 검색 · 기준일 · 칩 · 페이저 규칙은 [[구분자_화면기획]] §1 과 같다 (디바운스 300ms · 선택형 즉시 · URL 정본 ·
  이전/다음은 여러 페이지일 때만). 검색은 **값 표시명까지** 잡는다 — 「간편심사」 를 치면 심사유형이 나온다.
- 컬럼

| 컬럼 | 폭 | 필터 | 비고 |
|---|---|---|---|
| 코드 | mono 104px | 검색창 | |
| 표시명 | 남는 폭 | 검색창 | 클릭 → 상세(§2) |
| 값 | 고정 (넓게) | — | 순서대로 「일반심사 · 간편심사 · 무심사」. 넘치면 「… 외 N」 |
| 수 | 고정, 우측 정렬 `tabular-nums` | — | 값 개수 |
| 사용처 | 고정 | 헤더 `▾` → 있음 · 없음 | 참조하는 구분자 · 필드 수. 0 이면 「—」. 지워도 되는 것을 찾는 용도 |

- 지금 구현(`/catalog/enums`)의 **한 페이지에 전부 펼쳐 놓고 인라인 편집**하는 방식은 버린다 — 선택지가 스무 개를 넘으면
  스크롤로 찾는 화면이 된다. 목록 → 상세로 나눈다.

### 상세 (`/types/enums/<code>`) — L2

- 편집 흐름은 [[02_UI/디자인원칙]] §2 L2 「편집 흐름」 — 읽기 모드 기본, 우측 상단 「편집」 → 「저장」 하나. 값 표의 표시명 · 순서도
  편집 모드에서만 바뀌고 저장 한 번에 반영된다 (행마다 저장 버튼 없음).
- 헤더: 표시명 · 코드(mono, 잠김) · 사용처 N (클릭 → 관계정보) · 우측 상단 편집/저장 · 🗑.
- 값 표: 순서 · 코드(mono) · 표시명 · 사용 수 · 삭제(아이콘, `.danger`, Confirm — 편집 모드에서만 보인다).
  드래그 손잡이로 순서 변경 (액션 「값 순서 변경」 — 폼 선택지 표시 순서).
- 표 아래 「값 추가」 한 줄 입력 — 표시명만, Enter 로 추가. 코드 자동 채번.
- 선택지 삭제는 헤더 오른쪽 끝 아이콘. 사용처가 있으면 거부 + 사용처 목록 (액션 「enum 정의 삭제」 거부 열).

## 2. 선택지 생성 (`/types/enums/new`) — L2

| 필드 | 입력 | 비고 |
|---|---|---|
| 표시명 | 텍스트, 필수 | 중복 거부 〔D-P1-7〕 |
| 값 | 한 줄에 하나, 여러 줄 | 「일반심사 / 간편심사 / 무심사」. 콤마 구분(지금 구현)보다 줄 구분 — 값 표시명에 콤마가 들어갈 수 있다 |
| 설명 | 선택 | |

- 생성 → 상세로. 값이 0개여도 생성은 된다 — 값은 상세에서 늘린다.
- 조회 화면의 검색어가 있으면 표시명에 프리필 (§9.1 — 찾다가 없어서 만드는 흐름).

## 3. 폼 조회 (`/types/forms`)

### 목적

폼(구조체)의 목록. 어떤 폼이 어느 레벨에 붙어 몇 개 필드를 묻는지 한눈에.

### 화면 구성

컬럼 필터 · 칩 · 페이저 규칙은 §1 과 같다.

| 컬럼 | 폭 | 필터 | 비고 |
|---|---|---|---|
| 코드 | mono 104px | 검색창 | 구분자 코드 그대로 (`D0002`) |
| 표시명 | 남는 폭 | 검색창 | 클릭 → 상세(§4) |
| 레벨 | 고정 | 헤더 `▾` | 상품 · 세목 · 담보 · 세부보장 · 급부 |
| 노출 | 고정 | 헤더 `▾` | 무조건 · 선택 |
| 필드 | 고정, 우측 정렬 | — | 필드 수. 0 이면 `0` 을 그대로 — 필드 없는 구조체는 만들다 만 것이다 |
| 사용처 | 고정 | 헤더 `▾` → 있음 · 없음 | 값 행 · 식 · 문면 참조 수 |

- 검색은 **필드 표시명까지** 잡는다 — 「면책」 을 치면 그 필드를 가진 구조체가 나온다.
- 종류 컬럼은 없다 — 여기는 전부 폼이다.

### 상세 (`/types/forms/<code>`) — L2

- 편집 흐름은 §1 상세와 같다 (L2 「편집 흐름」). 필드 표의 표시명 · 타입 · 기본값 · 순서는 편집 모드에서 고치고 저장 한 번에 반영.
  필드 기본값 입력기는 필드 타입을 따른다 ([[구분자_화면기획]] §2 기본값 표).
- 헤더: 표시명 · 코드 · 사용처 N · 우측 상단 편집/저장 · 🗑. **레벨 ⓘ · 노출 ⓘ 는 헤더가 아니라 왼쪽 필드 그리드**에 둔다
  (2026-09-06 구현 확인 — 노출은 편집 대상이라 입력기가 있는 그리드가 정본이고, 헤더에 같이 두면 한 값이 두 번 보인다).
  레벨 · 노출 변경은 구분자 상세와 같은 규칙
  (액션 「부착 레벨 변경」 · 「노출여부 변경」). 「실체」 대신 「모델링」 (L2 「화면 단어」).
- 필드 표: 순서(드래그) · 코드(mono, `F01`) · 표시명 · 타입 · 선택지(타입이 선택형일 때 링크 → §1 상세) ·
  기본값 · 사용 수 · 삭제(아이콘, Confirm, 소실 값 목록).
- 표 아래 「필드 추가」 한 줄 — 표시명 · 타입 · (선택형이면) 선택지 고르기. 선택지 목록에 없으면 「새 선택지」 로 §2 를
  새 창이 아니라 **같은 화면의 다이얼로그**로 연다 — 필드 하나 만들다가 탭을 옮기지 않게.
- 「이 폼을 구분자로 보기」 링크 → `/catalog/<code>` (같은 실체의 다른 얼굴).

## 4. 폼 생성 (`/types/forms/new`) — L2

구분자 탭의 생성 화면에서 종류 = 폼을 고른 것과 **같은 입력 폼**이다 — 실체가 같으니 입력 폼도 하나여야 한다.
어느 탭에서 들어와도 생성 뒤에는 §3 상세로 간다 (첫 필드를 거기서 추가한다 — 리뷰 #21).

| 필드 | 입력 | 비고 |
|---|---|---|
| 표시명 | 필수 | 같은 레벨에 중복 거부 〔D-P1-1〕 |
| 레벨 | 셀렉트, 「담보」 프리필 + 「제안」 배지 | §9.1 |
| 노출 | 무조건 · 선택 | 기본 선택 |
| 설명 | 선택 | |

- 구분자 탭 생성 화면의 종류 선택에서 「폼」 을 고르면 이 입력 폼이 그 자리에 뜬다. 두 곳이 같은 컴포넌트를 쓴다.

## 예외 · 빈 상태

- 선택지 0건: EmptyState — 「선택지는 선택형 구분자가 고르는 값 목록이다」 + 예시(심사유형: 일반심사 · 간편심사) + 「새 선택지」.
- 폼 0건: EmptyState — 「폼은 값 여러 개를 한 번에 묻는 구분자다」 + 예시(납입면제: 면책여부 · 면제사유) + 「새 폼」.
- 사용처 있는 것을 삭제: 거부 + 사용처 목록. 개발자 권한 · 파괴적 액션 규칙은 [[06_결정/ADR-0019-모드폐지-역할권한]].

## 인수기준
> [[05_QA/인수기준]] 에 등록 (미등록)

- 좌측 내비에 「유형」 이 「구분자」 다음에 있고, 안에 선택지 · 폼 두 하위 탭이 있다.
- 선택지 조회에서 값 표시명으로 검색이 된다.
- 폼을 유형 탭에서 만들면 구분자 조회에도 종류 = 폼으로 잡힌다. 코드는 하나다.
- 화면 어디에도 「enum」 · 「구조체」 가 보이지 않는다.
