# 구분자 화면기획

> 상태: 초안 · 최종수정: 2026-09-09
>
> 대응 기획: [[01_기획/구분자_기획]] · 대응 액션: [[02_UI/유저액션/구분자_액션]] · 레이아웃: [[02_UI/디자인원칙]] §2 L1

구분자 탭의 화면 전부를 여기서 다룬다. 2026-09-06 에 **조회** · **상세** 에 QA 를 걸었고,
**2026-09-08~09 에 조회 · 상세 · 생성 셋 다 실물 화면을 놓고 다시 고쳤다** (§5 개정 목록).

2026-09-09 개정으로 바뀐 큰 두 가지 —
**폼은 이 탭에 나오지 않는다** ([[06_결정/ADR-0031-폼-구분자목록-분리]]) ·
**「종류」가 「유형」, 「단일값」이 「일반」이 됐다** ([[06_결정/ADR-0032-구분자유형-명칭-유형-일반]], Q-B 번복).

## 1. 조회 화면 (`/catalog`)

### 목적

카탈로그의 구분자 정의를 훑고, 조건으로 좁혀서, 하나를 골라 상세로 들어간다.
사용자는 **현업 담당자**다 — 화면의 단어는 개발 용어가 아니라 업무 용어여야 한다.

### 화면 구성

```
┌──────────────────────────────────────────────────────────┐
│ 구분자                                              [+]   │  제목 줄 · 오른쪽 끝에 「새 구분자」 아이콘 버튼
├──────────────────────────────────────────────────────────┤
│ 🔍 코드 · 표시명            기준일 [2026-09-09] □미확정 포함│  검색 + 이력일자 (sticky)
│ 유형: 파생 ✕   레벨: 담보 ✕                                │  걸린 필터 칩 (없으면 줄 자체가 없음)
├──────┬───────────┬────────┬────────┬──────────┬─────────┤
│ 코드 │ 표시명     │ 유형 ▾ │ 레벨 ▾ │ 최종수정  │ 수정자   │  컬럼 헤더에서 필터
├──────┴───────────┴────────┴────────┴──────────┴─────────┤
│ 총 N건                            (여러 페이지일 때만) ‹ › │  하단 고정
└──────────────────────────────────────────────────────────┘
```

**제목 줄**

- 오른쪽 끝에 **`+` 아이콘 버튼** 하나. tooltip 「새 구분자」(§1.6 — 아이콘 버튼은 tooltip 의무).
  텍스트 링크 「+ 새 구분자」 였던 것을 바꾼다.
- **「enum 목록」 버튼은 두지 않는다.** 선택지(enum)와 구조체는 별도 탭 [[유형_화면기획]] 이 관리한다
  (2026-09-06 확정).
- **폼은 이 목록에 나오지 않는다** (2026-09-09 · [[06_결정/ADR-0031-폼-구분자목록-분리]]).
  도메인에서 폼은 여전히 구분자지만([[06_결정/ADR-0001-폼구조체-구분자하나]]) 화면의 입구는
  「유형 > 폼」 하나다. 2026-09-06 의 절충(「조회에는 종류 = 폼으로 계속 잡힌다」)은 폐기한다.

**검색 + 이력일자 바** (sticky, §2 L1)

- **검색창** 하나. 코드 · 표시명 부분 일치. **「적용」 버튼 없음** — 입력하면 표가 따라 바뀐다.
  - 타이핑은 **디바운스 300ms** (마지막 키 입력 뒤 300ms 지나면 반영). 키마다 표를 다시 그리면 IME(한글 조합)
    중간 상태로 필터가 걸려 표가 깜빡인다. 쓰로틀보다 디바운스 — 조합이 끝난 최종 문자열 하나만 반영하면 된다.
  - 반영된 검색어는 URL 쿼리(`?q=`)에도 실린다 — 뒤로가기 · 링크 공유가 필터 상태를 잃지 않게. 히스토리는 `replace`
    (키 입력마다 히스토리 항목이 쌓이지 않게).
  - 선택형 필터(유형 · 레벨)와 기준일은 **디바운스 없이 즉시** 반영한다 — 고르는 행위가 곧 확정이다.
- **기준일(이력일자)** 선택. 기본 = 오늘. [[06_결정/ADR-0026-이력개정-이력일자-작업본확정]] 결 1 —
  「조회 · 생성 화면에 기준일 선택 UI (기본 = 오늘)」. 표는 기준일 이하 최신 확정 행을 보인다.
- **「미확정 포함」 토글**. 기본 꺼짐. 켜면 미적용(미확정 작업본) 레코드도 잡힌다 (ADR-0026 결 3).
- 이력 자체는 MVP 이후 구현이지만(ADR-0026), **화면 자리는 지금 잡는다** — 나중에 필터바를 다시 짜지 않게.
  구현 전까지는 기준일 = 오늘로 고정 표시, 조작 불가(잠긴 필드 — §1.2 출처 문법).

**필터 칩 줄**

- 컬럼 필터가 하나라도 걸리면 검색 바 아래에 **칩**으로 나열한다 — `유형: 파생 ✕`. 검색어는 검색창에
  그대로 보이므로 칩으로 만들지 않는다.
- 칩 오른쪽 끝 **✕** 로 그 필터 하나만 푼다. 칩이 0개면 줄을 그리지 않는다 (빈 줄이 필터바 높이를 먹지 않게).
- 칩이 있는 동안 검색 바 오른쪽 끝에 **「모두 지우기」** 텍스트 버튼. 칩 하나뿐일 때는 안 보인다 (✕ 와 같은 일).

**컬럼 헤더 필터** — 상단의 유형 · 레벨 셀렉트를 없애고 **각 컬럼 헤더에서 건다.**
§2 L1 「필터 항목은 표의 컬럼과 일치시킨다」를 배치로도 지키는 것이다.

| 컬럼 | 필터 | 비고 |
|---|---|---|
| 코드 | 검색창이 담당 | 헤더 필터 없음 |
| 표시명 | 검색창이 담당 | 헤더 필터 없음. 남는 폭을 먹는 유일한 컬럼 (§2 L1) |
| 유형 | 헤더 `▾` → 값 하나 선택 | 일반 · 상수 · 파생 (명칭은 아래). **폼은 없다** |
| 레벨 | 헤더 `▾` → 값 하나 선택 | 상품 · 세목 · 담보 · 세부보장 · 급부. 상수는 레벨이 없으므로 레벨 필터를 걸면 빠진다 |
| 최종수정 | 필터 없음 | 날짜만 (`YYYY-MM-DD`) · mono 로 세로줄을 맞춘다 |
| 수정자 | 필터 없음 | 마지막으로 저장한 사람의 **이름**. 도메인은 사용자를 모르므로 id → 이름은 화면이 붙인다 |

**노출 컬럼은 없다** (2026-09-09). 폼 목록([[유형_화면기획]] §3)에는 필요하지만 여기서는
상수 · 파생이 늘 「—」라 컬럼 하나가 거의 비어 있게 된다. 노출은 상세에서 본다.

- 헤더 `▾` 를 누르면 그 컬럼의 값 목록이 팝오버로 뜬다. 하나를 고르면 즉시 반영 + 칩 생성 + 팝오버 닫힘.
- 필터가 걸린 컬럼은 헤더의 `▾` 가 채워진 형태(`▼`)로 바뀐다 — 칩을 못 봐도 헤더만으로 「여기 걸려 있다」가 보인다.
- 컬럼당 값 하나(단일 선택). 복수 선택은 지금 필요가 없다 — 필요해지면 그때 결정.

**유형 명칭 — 「스칼라」 · 「구조체」를 쓰지 않는다** (2026-09-06) · **필드명은 「유형」** (2026-09-09)

| 도메인 kind | 화면 라벨 (2026-08-30) | 2026-09-06 | 2026-09-09 (현재) |
|---|---|---|---|
| `scalar` | 스칼라 | 단일값 | **일반** |
| `struct` | 구조체 | **폼** | 폼 (이 목록엔 안 나옴) |
| `const` | 상수 | 상수 | 상수 |
| `derived` | 파생 | 파생 | 파생 |

「스칼라」 · 「구조체」는 개발자 용어다. 폼은 「값 여러 개를 한 번에 묻는 구분자」로 현업에게 바로 읽힌다 —
용어사전의 「폼 하나 = 구조체 타입 구분자 하나」를 화면 라벨로 옮긴 것이다.

**「단일값」 → 「일반」은 2026-09-06 Q-B 를 뒤집은 것**이다 ([[06_결정/ADR-0032-구분자유형-명칭-유형-일반]]).
그때는 「일반 vs 폼」을 갈라야 해서 「일반」이 흐리다고 봤는데, 폼이 목록에서 빠진 뒤로는
남은 셋을 가르는 축이 「값이 몇 개냐」가 아니라 「사람이 채우냐 · 마스터에 있냐 · 계산되냐」다.
필드명 「종류」 → 「유형」도 같은 결정에 딸린다 — 다만 **「유형」이 세 자리에서 다른 것을 가리키는 충돌이 남아 있다** (Q-E).

문서 · 코드의 도메인 용어는 그대로 `scalar` · `struct` 다. 라벨은 `src/app/_lib/labels.ts` 의 `KIND_LABEL`
한 곳에서 바꾼다 (§9 — 영문 값이 화면에 새지 않게 라벨 맵 한 곳만 통과).

**표**

- 컬럼: 코드 · 표시명 · 유형 · 레벨 · 최종수정 · 수정자 (2026-09-09).
- 1열 코드 mono 104px, 표시명이 남는 폭, 나머지는 고정폭 (§2 L1).
- **표시명에 밑줄을 긋지 않는다** — 행마다 이름이 링크라 밑줄이 다 그어지면 괘선과 싸운다.
  누를 수 있다는 것은 hover 의 주칠이 말한다 (§1.3).
- 표시명 클릭 → 상세(§2).

**하단 고정 줄**

- **총 N건** 은 항상 보인다 (몇 건 중 몇 번째인지가 늘 보여야 한다 — §2 L1).
- **‹ 이전 · 다음 ›** 는 **페이지가 둘 이상일 때만** 그린다. 한 페이지면 조작할 것이 없는 버튼을 보여 주지 않는다.
- 여러 페이지에서 첫 페이지면 「이전」 비활성, 마지막 페이지면 「다음」 비활성. `p/P` 표시는 여러 페이지일 때만.
- 페이지 크기 50. 필터를 바꾸면 1페이지로 돌아간다.

### 조작과 상태 전이

| 조작 | 결과 |
|---|---|
| `+` 클릭 | 생성 화면(§3)으로. 조회에 걸린 필터(유형 · 레벨)가 생성 폼의 초기값으로 넘어간다 (§9.1 스마트 디폴트) |
| 검색어 입력 | 300ms 뒤 표 갱신 · URL `?q=` 갱신 · 1페이지로 |
| 헤더 `▾` 에서 값 선택 | 즉시 표 갱신 · 칩 추가 · 헤더 `▼` · 1페이지로 |
| 칩 ✕ | 그 필터 해제 · 표 갱신 · 헤더 `▾` 복귀 |
| 모두 지우기 | 컬럼 필터 전부 해제. 검색어 · 기준일은 유지 |
| 기준일 변경 | 즉시 표 갱신 (이력 구현 후) |
| 미확정 포함 토글 | 즉시 표 갱신 (이력 구현 후) |
| 표시명 클릭 | 상세(§2) |
| 이전 · 다음 | 페이지 이동. 필터 · 검색어 · 기준일 유지 |

URL 이 상태의 정본이다 — `?q=&kind=&level=&asOf=&draft=&page=` (`exposure` 는 2026-09-09 에 뺐다). 새로고침 · 뒤로가기 · 링크 공유가 같은 화면을 준다.

### 예외 · 빈 상태 · 오류

- **카탈로그 자체가 비었을 때**: 표 대신 EmptyState — 구분자가 무엇인지 한 줄 + 예시 + 「새 구분자 만들기」 (§9.3).
- **필터 탓에 0건**: 「이 조건에 맞는 구분자가 없습니다」 한 줄 + 칩은 그대로 (무엇을 풀면 되는지 보이게).
- **검색어가 조합 중**(IME): 디바운스가 흡수한다. 조합 중간 문자열로 0건이 잠깐 뜨는 것을 막는다.

### 인수기준
> [[05_QA/인수기준]] 에 등록 (미등록)

- 검색창에 「갱신」 을 치면 버튼 없이 300ms 안에 표가 좁혀지고 URL 에 `q=갱신` 이 실린다.
- 유형 헤더에서 「파생」 을 고르면 칩 `유형: 파생 ✕` 가 생기고, ✕ 를 누르면 원래 표로 돌아온다.
- 유형 필터의 선택지에 「폼」 이 없고, 표에 폼이 한 건도 나오지 않는다.
- 총 건수가 페이지 크기 이하면 이전 · 다음이 화면에 없다.
- 화면 어디에도 「스칼라」 · 「구조체」 · 「enum」 · `scalar` 같은 개발 용어가 보이지 않는다.
- 표시명 링크에 밑줄이 없다.

## 2. 상세 · 수정 화면 (`/catalog/<code>`)

> 2026-09-06 QA 반영. 편집 흐름은 [[02_UI/디자인원칙]] §2 L2 「편집 흐름」 — 읽기 모드가 기본, 우측 상단 「편집」 → 「저장」.

### 목적

구분자 하나를 한눈에 보고, 필요하면 고친다. 어디서 쓰이는지가 같은 화면에 있어야 「고쳐도 되나」를 판단한다.

### 화면 구성 — 1열 (2026-09-09 개정)

```
┌──────────────────────────────────────────────────────────────┐
│ ← 구분자 목록                        [사용처 3] [편집] [🗑]    │  헤더: 돌아가기 + 조작. 이름 · 코드 없음
├──────────────────────────────────────────────────────────────┤
│ 코드      D0007                                               │  글자 (여기서 못 고침)
│ 유형      일반                                                │  글자
│ 레벨 ⓘ    담보                                                │  글자
│ 구분자명  [갱신여부              ]                             │  읽기 = 회색 칸 · 편집 = 입력칸
│ 노출      ◉ 무조건  ○ 선택                                     │
│           이 레벨의 모든 모델링에 값 자리가 생긴다 — 붙이는 조작 없이. │  고른 값의 뜻풀이
│ 타입      [예/아니오 ▾]                                        │
│ 기본값 ⓘ  [예 ▾]                                              │
└──────────────────────────────────────────────────────────────┘
```

**좌우 2열을 폐기하고 1열로 돌아갔다** (2026-09-09). 사용처를 옆에 상시로 펼쳐 두니 고칠 필드보다
자리를 더 먹었다. `.ts-l2-split` 을 쓰는 마지막 화면이었다.

- **헤더에는 이름 · 코드 · 사용처 수를 적지 않는다.** 같은 값이 아래 필드와 사용처 모달에 그대로 있다.
  제목이 빠져 헤더 줄이 비므로 **「← 구분자 목록」이 그 자리로 올라온다** — 나가는 길과 이 화면의 조작이 한 줄에 놓인다.
  (`EditShell` 의 `bareHead`. 다른 편집 화면은 기존 헤더 그대로다.)
- **코드가 첫 필드다.** 헤더에서 뺀 코드가 갈 자리는 필드 맨 위다.
- **사용처는 모달**이다. 헤더의 `사용처 N` 버튼 → `showModal()` 로 연다 (backdrop · ESC 있음).
  건수는 「N / 전체 참조 M」 분모와 함께 (§9.6). 0건이면 「아무 문면 · 식도 이 구분자를 읽지 않는다」 + 「문면에서 쓰러 가기」.
  **편집 모드에서는 이 버튼이 사라진다** — 편집 중에는 저장 · 취소가 유일하게 해야 할 일이다.
- **여기서 아예 못 고치는 값(코드 · 유형 · 레벨)은 글자로 둔다.** 읽기 모드의 값과 같은 회색 칸을 입히면
  「편집」을 눌러도 안 바뀌는 칸이 왜 그대로인지 화면에 설명이 없다.
  `.ts-field-static`(칠 없음) 과 `.ts-field-locked`(회색 칸 = 지금은 못 고침)를 가른다.
- **설명 필드는 없다** (2026-09-09). 저장된 설명 값은 지워지지 않는다 — 초기 데이터에 실려 그대로 다시 쓰인다.
  화면에서 손댈 방법이 없어졌을 뿐이다.
- **위험 구역 섹션은 없다.** 삭제는 헤더 오른쪽 끝 `.danger` 휴지통 아이콘(tooltip 「구분자 갱신여부(D0007) 삭제 — 저장된 값 N건이 사라진다」)
  → 확인 팝업. 타입 변경은 편집 모드의 타입 필드에서.
- **편집 모드의 행 여백은 읽기 모드보다 넓다.** 편집 모드는 값이 전부 테두리 있는 입력칸이라
  같은 행간이면 칸끼리 맞닿는다. 라디오 + 뜻풀이처럼 한 줄을 넘는 행은 라벨을 위로 맞춘다.

### 헤더 조작

| 모드 | 우측 상단 | 비고 |
|---|---|---|
| 읽기 | 「사용처 N」 · 「편집」 · 🗑 | 고칠 수 있는 필드는 잠긴 칸, 코드 · 유형 · 레벨은 글자 |
| 편집 | ✕ · 「저장」 · 🗑 | 「사용처」는 감춘다. 저장은 변경이 있을 때만 활성. ✕ 는 변경 있으면 「계속 편집 / 버리기」 팝업 |
| 저장 중 | 전부 disabled | 끝나면 읽기. 거부되면 편집 유지 + 사유 배너 |

### 필드 — 유형별

| 필드 | 읽기 | 편집 | 비고 |
|---|---|---|---|
| 코드 | `D0007` mono | 못 바꾼다 | 첫 필드 (2026-09-09). 시스템 채번 · 불변 — [[06_결정/ADR-0005-코드-표시명-이중체계]] |
| 유형 | 일반 · 상수 · 파생 | 못 바꾼다 | 폼 코드로 들어오면 폼 탭으로 리다이렉트되므로 여기서 「폼」은 안 나온다 (ADR-0031) |
| 레벨 ⓘ | 상품 · 세목 · 담보 · 세부보장 · 급부 | **지금은 못 바꾼다** (읽기 전용) — 서비스에 레벨 변경이 없다 (2026-09-06 확인). 액션 명세에는 있다 → Q-D | ⓘ 「이 구분자가 붙는 모델링의 층. 담보에 붙이면 담보마다 값을 갖는다」. 상수는 이 행이 없다 |
| 구분자명 | 텍스트 | 입력 | 라벨을 「표시명」 → 「구분자명」으로 통일 (2026-09-09) |
| 노출 | 무조건 · 선택 | **라디오 2지선다** + 고른 값의 뜻풀이 한 줄 | 체크박스였을 때는 「선택」이 이름 없이 꺼진 칸으로만 있었다. ⓘ tooltip 은 뜻풀이와 같은 말이라 걷었다. 일반 · 폼만 |
| 타입 | 「예/아니오」 · 「선택형 (고지유형)」 | 셀렉트 (+ 선택형이면 선택지 셀렉트). 바꾸면 기본값 칸이 새 타입의 입력기로 바뀌고 값은 비워진다 | 일반만. 저장 시 저장된 값 N건 소실 확인 팝업 (§9.5) |
| 기본값 ⓘ | 값 또는 「없음」 | **타입을 따르는 입력기** — 아래 표 | 일반만. ⓘ 「폼을 열 때 미리 채워 보여줄 제안. 사람이 저장해야 값이 된다」 |
| 값 | 텍스트 | 입력 | 상수만 |
| 식 | mono | mono 입력. 저장 전에 식 검사 | 파생만 |
| 필드 | — | — | **폼은 이 화면에 오지 않는다** (ADR-0031). 폼 코드로 들어오면 `/types/forms/<code>` 로 리다이렉트 |

**기본값은 타입이 정한 입력기로 받는다** (2026-09-06 QA #4). 지금 구현은 타입과 무관한 자유 텍스트 칸이라 「무슨 값을 넣으라는 건지」가
안 보였다. [[01_기획/구분자_기획]] 의 전제(기본값 = 선택 항목 · 프리필 전용)는 유지하고, 입력기만 타입에 맞춘다.

| 타입 | 기본값 입력기 |
|---|---|
| 문자열 | 텍스트 |
| 숫자 | 숫자 (우측 정렬 · `tabular-nums`) |
| 예/아니오 | 셀렉트 「없음 · 예 · 아니오」 |
| 날짜 | 날짜 선택 |
| 선택형 | 그 선택지의 값 셀렉트 + 「없음」 |
| 선택형(복수) | 그 선택지의 값 다중 선택 |

타입이 아직 없는 자리(생성 폼)에는 기본값 칸을 두지 않는다 — 생성은 타입까지만 받고 기본값은 상세에서 넣는다.

### 조작과 상태 전이

| 조작 | 결과 |
|---|---|
| 편집 | 편집 모드. 고칠 수 있는 필드가 입력기로 바뀐다. 코드 · 유형 · 레벨은 글자 그대로. 「사용처」 버튼은 감춰진다 |
| 값 변경 | 「저장」 활성 |
| 저장 (타입 그대로) | 액션 「표시명 변경」 · 「노출여부 변경」 · 「기본값 지정 · 해제」 · 「const 값 변경」 · 「파생식 수정」 을 한 번에. 설명은 화면에 없지만 원래 값이 그대로 다시 쓰인다. 읽기 모드로 |
| 저장 (타입 바뀜) | 확인 팝업 「타입 바꾸고 값 N건 삭제」 → 확인하면 위 + 「타입 변경」. 취소하면 편집 모드 유지 |
| 저장 (레벨 바뀜) | 지금 없음 — 레벨은 읽기 전용 (Q-D) |
| ✕ | 변경 없으면 읽기 모드. 있으면 「계속 편집 / 버리기」 |
| 🗑 | 확인 팝업 (저장된 값 N건 · 사용처 M건). 사용처가 있으면 거부 + 사용처 목록 — 액션 「구분자 삭제」 |
| 사용처 N | 모달이 열린다 (backdrop · ESC 로 닫힘) |
| 사용처 행 클릭 | 그 좌표(문면 · 식)로 이동 |

### 예외 · 빈 상태 · 오류

- 없는 코드: 「찾을 수 없습니다」 + 목록 링크.
- 사용처 0건: 위 빈 상태 문구.
- 저장 거부(권한 · 중복 표시명 등): 편집 모드 유지 + 사유 배너. 입력한 값은 남는다.

### 인수기준
> [[05_QA/인수기준]] 에 등록 (미등록)

- 들어가면 모든 필드가 잠긴 칸이고 「편집」 을 눌러야 입력기가 된다. 「저장」 은 값을 바꾸기 전엔 비활성이다.
- 예/아니오 타입 구분자의 기본값 칸은 「없음 · 예 · 아니오」 셀렉트다. 자유 텍스트가 아니다.
- 화면 어디에도 「실체」 · 「스칼라」 · 「위험 구역」 이 없다. 레벨 · 기본값 라벨 옆에 ⓘ 가 있고 hover 하면 한 줄 설명이 뜬다.
- 헤더에 구분자명 · 코드 · 사용처 수가 없다. 코드는 첫 필드에 있다.
- 코드 · 유형 · 레벨은 「편집」 을 눌러도 회색 칸이 되지 않고 글자 그대로다.
- 「사용처 N」 을 누르면 모달이 뒤를 어둡게 하고 열리며, ESC 로 닫힌다. 편집 모드에서는 그 버튼이 없다.
- 노출은 「무조건 · 선택」 라디오이고, 고른 쪽의 뜻풀이 한 줄이 아래에 뜬다.

## 3. 생성 화면 (`/catalog/new`)

> 2026-09-09 에 뼈대에서 실물로. 조회에서 넘어온 필터 값을 프리필한다 (§9.1).
> 생성은 타입까지만 받는다 — 기본값 칸 없음 (§2). **폼은 여기서 만들지 않는다** ([[06_결정/ADR-0031-폼-구분자목록-분리]]).

### 화면 구성

```
┌──────────────────────────────────────────────────────────────┐
│ 새 구분자                                            [생성]   │  제출은 헤더 우측
├──────────────────────────────────────────────────────────────┤
│ 구분자명  [                    ]                              │
│ 레벨      ○상품 ○세목 ◉담보 ○세부보장 ○급부                    │
│ 유형      ◉일반 ○상수 ○파생                                    │
│ 타입      [문자열              ▾]                             │  일반만
│ [선택지]  [— 고르기 —          ▾]                             │  타입이 선택형일 때만
│ 노출      ◉선택 ○무조건                                        │  일반만
│           담보 · 상품 화면에서 이 구분자를 붙인 곳에만 값 자리가 생긴다. │
└──────────────────────────────────────────────────────────────┘
```

- **2열 그리드** — 라벨 좌측 · 값 우측 (§2 L2). 세로로 늘이지 않아야 만들 것 전체가 한 화면에 들어온다.
  1열 스택 · 유형 카드 · 중요도 2단(주요/부가)을 차례로 시험했다가 전부 버렸다 (§5).
- **폼은 하나다.** 유형마다 `<form>` 을 따로 두면 유형을 바꿀 때 입력이 통째로 날아간다.
  폼 하나에 서버 액션만 고른 유형의 것으로 갈아 끼운다 (`actions.ts` 는 안 건드린다).
- **구분자명 · 레벨은 유형 위에 있고, 유형을 바꿔도 값이 남는다.** 유형과 무관한 칸이기 때문이다.
- **유형에 따라 달라지는 칸은 `hidden` 이 아니라 실제로 뺀다** — 안 쓰는 칸의 `required` 가 DOM 에 남아 있으면
  보이지도 않는 칸 때문에 제출이 막힌다.
  - 상수는 부착 레벨이 없으므로(`ConstDiscriminator`) **레벨 칸이 내려간다.** 고른 값은 상태로 쥐고 있어 되돌아오면 그대로다.
- **「선택지」는 타입이 선택형일 때만 나타난다.** 늘 띄워 두고 라벨에 「(타입이 선택형일 때만)」이라 적어 두면
  대부분의 경우 못 쓰는 칸 하나가 화면에 남는다.
- **제출은 헤더 우측의 「생성」** (화면 하단에 조작을 두지 않는다 — §2 L2).
  폼 밖에 있으므로 `form={...}` 으로 지금 고른 유형의 폼을 가리킨다. 폼 밖이어도 `required` 검증은 그대로 걸린다.
- **레벨의 「제안」 배지는 없앴다** (2026-09-09). 프리필 자체는 유지한다 (§9.1) — 배지 없이도 골라져 있는 것이 보인다.
- **설명 칸은 없다** (2026-09-09).

### 유형별 칸

| 유형 | 공통 위에 붙는 칸 |
|---|---|
| 일반 | 타입 · (선택형이면) 선택지 · 노출 |
| 상수 | 값. **레벨 없음** |
| 파생 | 식 (mono) |

### 인수기준
> [[05_QA/인수기준]] 에 등록 (미등록)

- 구분자명과 레벨을 채운 뒤 유형을 일반 → 상수 → 파생 → 일반으로 옮겨도 두 값이 그대로다.
- 상수를 고르면 레벨 칸이 사라지고, 다시 일반으로 오면 아까 고른 레벨이 그대로 있다.
- 타입을 「선택형」으로 바꾸면 선택지 칸이 나타나고, 문자열로 되돌리면 사라진다.
- 구분자명을 비운 채 「생성」 을 누르면 제출이 막히고 그 칸으로 포커스가 간다.
- 유형 선택지에 「폼」 이 없다.
