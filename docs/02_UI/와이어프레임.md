# 와이어프레임 — 실물 화면

> 상태: 초안 · 최종수정: 2026-09-09
>
> 기준: `main` (b7c5b55) · 레이아웃 근거: [[02_UI/디자인원칙]] §2 · 라벨 출처: `src/app/_lib/labels.ts`

**지금 `main` 에 있는 화면을 있는 그대로 옮긴 그림이다.** 기획이 아니다 —
「이렇게 되어야 한다」는 `02_UI/화면/*_화면기획` 이 말하고, 이 문서는 **「지금 이렇다」**만 적는다.
그래서 화면기획과 어긋나는 자리가 있다. 어긋난 목록은 §22 에 모았다.

> **주의 — 문서가 코드보다 앞서 있다.** 2026-09-09 화면 QA 1회차의 코드는 **커밋되지 않았다**
> ([[05_QA/화면QA_이력]] 「남은 것」 마지막 줄). 그래서 구분자 탭 · 별표 화면 · 공용 조각
> (`ListPage` · `FormRow` · `RadioGroup` · `Combobox` · `NoteField` · `UsageDialog`)은 `main` 에 없다.
> 화면기획을 읽고 화면을 찾으면 안 보이는 이유가 이것이다.

## 읽는 법

| 기호 | 뜻 |
|---|---|
| `[ 텍스트 ]` | 입력칸 (테두리 = 고칠 수 있다 — §1.2) |
| `[ 값 ▾ ]` | 셀렉트 |
| `( ) 값` | 라디오 · `☐ 값` 체크박스 |
| `〔버튼〕` | 버튼 · `〔🗑〕` 아이콘 버튼 (tooltip 의무 — §1.6) |
| `종류 ▾` | 컬럼 헤더가 곧 필터 (팝오버) |
| `값` (민무늬) | 글자 — 여기서 못 고친다 |
| `ⓘ` | 라벨 옆 tooltip |

칸 너비는 실제 CSS 비율을 따라 그렸다 (내비 168px · L3 는 196 / 남는 폭 / 360).

## 4. 구분자 목록 (`/catalog`)

```
┌──────────────────────────────────────────────────────────────────────┐
│ 구분자                                                          〔+〕 │  제목 줄 우측 아이콘 · tooltip 「새 구분자」
├──────────────────────────────────────────────────────────────────────┤
│ 🔍[코드 · 표시명            ]        〔모두 지우기〕 기준일[2026-09-09] ☐미확정 포함│
│ 종류: 파생 ✕   레벨: 담보 ✕                                            │  걸린 필터 칩 (0개면 줄 없음)
├────────┬────────────────────────────┬─────────┬─────────┬───────────┤
│ 코드    │ 표시명                      │ 종류 ▾  │ 레벨 ▾  │ 노출 ▾    │
├────────┼────────────────────────────┼─────────┼─────────┼───────────┤
│ D0007  │ 갱신여부                     │ 단일값   │ 담보    │ 선택      │
│ D0003  │ 납입면제                     │ 폼      │ 담보     │ 무조건     │
│ D0011  │ 보험기간                     │ 파생    │ 담보     │ —        │
├────────┴────────────────────────────┴─────────┴─────────┴───────────┤
│ 총 11건 · 1/1                                                        │  여러 페이지일 때만 이전 · 다음
└──────────────────────────────────────────────────────────────────────┘
```

- **검색**은 버튼 없이 반영된다 — 디바운스 300ms · IME 조합 중에는 멈춘다 · URL `?q=` 에 `replace` 로 싣는다 (`ListFilterBar`).
- **컬럼 헤더가 곧 필터**다. `▾` → 팝오버에서 값 하나. 걸리면 `▼` 로 바뀌고 칩이 생긴다.
  칩이 **2개 이상**일 때만 「모두 지우기」가 나온다.
- **기준일 · 미확정 포함은 자리만 있고 잠겨 있다** (`disabled`, tooltip 「이력 기능 준비 중」) — [[06_결정/ADR-0026-이력개정-이력일자-작업본확정]].
- 표 컬럼은 **코드 · 표시명 · 종류 · 레벨 · 노출** 다섯이다. 최종수정 · 수정자는 없다.
- 종류 필터의 선택지는 **단일값 · 폼 · 상수 · 파생** — 폼이 이 목록에 그대로 나온다.
- 페이지 크기 50. 빈 목록이면 EmptyState(무엇인지 + 예시 + 「새 구분자 만들기」), 필터 탓 0건이면 한 줄.
- URL 이 상태의 정본 — `?q=&kind=&level=&exposure=&page=`. `+` 버튼은 걸린 `kind` · `level` 을 생성 화면으로 물려준다.

## 5. 새 구분자 (`/catalog/new`)

```
┌──────────────────────────────────────────────────────────────────────┐
│ 새 구분자                                                             │
│ (◉) 단일값   ( ) 폼   ( ) 상수   ( ) 파생                              │  라디오 1줄로 고른다
├──────────────────────────────────────────────────────────────────────┤
│ 표시명       [                          ]                             │  ← 고른 종류의 폼 하나만 보인다
│ 레벨         [ 담보                  ▾ ] 〔제안〕                       │    (나머지 셋은 hidden 으로 DOM 에 남는다)
│ 타입         [ 문자열                ▾ ]                              │
│ 선택지 (타입이 선택형일 때만) [ —      ▾ ]                              │  항상 보인다
│ 무조건 노출   ☐                                                       │
│ 설명         [                          ]                             │
│                                          〔단일값 구분자 생성〕         │  제출은 폼 하단
└──────────────────────────────────────────────────────────────────────┘
```

종류마다 폼이 다르다 (칸 이름은 실물 그대로).

| 종류 | 칸 | 제출 버튼 |
|---|---|---|
| 단일값 | 표시명 · 레벨〔제안〕 · 타입 · 선택지 · 무조건 노출 ☐ · 설명 | 「단일값 구분자 생성」 |
| 폼 | 표시명〔제안〕 · 레벨〔제안〕 · 노출 ☐무조건 · 설명 (`StructCreateForm`) | 「폼 생성」 |
| 상수 | 표시명 · 값 · 설명 (**레벨 없음**) | 「상수 구분자 생성」 |
| 파생 | 표시명 · 레벨〔제안〕 · 식(mono) · 설명 | 「파생 구분자 생성」 |

- `KindPicker` 는 4개 폼을 **전부 렌더해 두고 `hidden` 으로 가린다** — 종류를 바꿔도 입력이 살아 있는 이유이자,
  안 보이는 칸의 `required` 가 DOM 에 남는 이유이기도 하다.
- 레벨의 기본값은 `coverage`(담보)이고 옆에 〔제안〕 배지가 붙는다 (§9.1).

## 6. 구분자 상세 · 수정 (`/catalog/<code>`)

```
← 구분자 목록
┌──────────────────────────────────────────────────────────────────────┐
│ 갱신여부  D0007  사용처 3                        〔편집〕 〔🗑〕        │  헤더 = 이름 · 코드 · 메타 · 조작
├───────────────────────────────────────┬──────────────────────────────┤
│ 종류      단일값                        │ 사용처  3 / 전체 참조 41       │  우측 aside (.ts-l2-split, 40%)
│ 레벨 ⓘ    담보                          │ ┌──────┬───────────────────┐│
│ 표시명    [ 갱신여부              ]      │ │ 형태  │ 좌표              ││
│ 설명      [                      ]      │ ├──────┼───────────────────┤│
│ 노출 ⓘ    ☐ 무조건 — 이 레벨의 모든        │ │조건식 │ 담보약관 › 제3조… ││
│           모델링에 값 자리를 만든다        │ │치환   │ 보통약관 › 제5조… ││
│ 타입      [ 예/아니오            ▾ ]     │ └──────┴───────────────────┘│
│ 기본값 ⓘ  [ 예                   ▾ ]     │                              │
└───────────────────────────────────────┴──────────────────────────────┘
```

- **읽기 모드가 기본**이다. 값은 회색 칸(`.ts-field-locked`), 「편집」을 눌러야 입력기가 된다 (§2 L2).
- 편집 모드 헤더: `〔✕〕 〔저장〕 〔🗑〕` — 저장은 변경이 있을 때만 활성, ✕ 는 변경이 있으면 「계속 편집 / 버리기」 팝업.
- 저장 · 삭제가 값을 잃게 하면 **먼저 세어 보여준다** (`ts-dialog`: 「사람이 입력한 값 N건이 사라진다」 · 함께 삭제 · 깨질 참조 — §9.5).
- 종류 · 레벨은 회색 칸이지만 **편집 모드에서도 안 바뀐다** (읽기 전용).
- 종류별로 아래 칸이 갈린다.

| 종류 | 추가로 보이는 것 |
|---|---|
| 단일값 | 노출 ☐ · 타입(+선택형이면 선택지 셀렉트) · 기본값(타입을 따르는 입력기) |
| 폼 | 노출 ☐ · **필드 표(읽기 전용: 코드 · 표시명 · 타입 · 기본값)** + 「폼 탭에서 편집 →」 |
| 상수 | 값 |
| 파생 | 식 (mono) |

- 폼 코드로 들어와도 **리다이렉트되지 않는다** — 이 화면이 읽기 전용 표로 받는다.
- 사용처가 0건이면 aside 가 「아무 문면 · 식도 이 구분자를 읽지 않는다」 + 「문면에서 쓰러 가기 →」.
- 사용처 좌표는 누르면 그 자리(문면 · 상품 …)로 간다 (`coordinateHref`).

```
│ 담보명   [ 일반상해사망보장          ]       │ 사용처                    │

│   └ 1 일반상해사망           급부 1                                     │  이름은 편집 모드에서 인라인 입력
│      └ 1 사망보험금                                                    │  읽기 모드에서 누르면 그 층 탭으로 점프
└──────────────────────────────────────────────────────────────────────┘
```

값 탭(담보 · 세부보장 · 급부)은 좌 목록 + 우 값 폼이다. 담보 탭은 노드가 하나라 좌측 목록이 없다.

```
├──────────────────┬───────────────────────────────────────────────────┤
│ 1 일반상해사망 2/3 │ 일반상해사망 — 값                                   │
│ 2 후유장해    0/3 │  ┌ 납입면제 ─────────────────────────────┐         │
│                  │  │ 면책여부 [ 예 ▾ ]   면제사유 [      ▾ ] │         │
│                  │  └──────────────────────────〔🗑 부착 해제〕┘        │
│                  │  부착 가능    〔+ 갱신여부〕 〔+ 고지유형〕            │  편집 모드에서만
└──────────────────┴───────────────────────────────────────────────────┘
```

- 좌측 목록의 `2/3` 은 「값 자리 3 중 2 입력」 (§9.2 목표 구배).
- **탭 전환은 클라이언트 상태**다 — 탭을 옮겨도 편집 모드와 변경분이 남는다. URL `?tab=` 은 `replaceState` 로 따라만 간다.
- **구조(세부보장 · 급부의 추가 · 삭제 · 순서)는 여기 없다.** 담보를 만들 때 정한다.
- 담보명에 담보속성 값(예: 「상해」)이 섞이면 경고 한 줄이 뜬다 — 막지는 않는다.
- 문면이 없고 편집 모드면 그 자리에서 「문면 제목 [ ] 〔문면 생성〕」이 나온다.

전폭 화면. 세로는 바 한 줄 + 남는 높이 하나, 가로는 **196 / 남는 폭 / 360** 이다.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 일반상해사망 특별약관  특별약관  조 5 · 검증 오류 0 / 노드 87   ← 문면 목록  〔✎〕│  ✎ = 편집 (편집 모드면 ✕ · ✓)
├───────────────┬──────────────────────────────────────┬───────────────────────┤
│ 제1조(보험금)   │            일반상해사망 특별약관         │  사전평가 · 미리보기    │
│ 제2조(지급사유) │                                       │   (읽기 모드)          │
│ 제3조(면책)    │  제1조(보험금의 지급사유)                 │  ─────────────────    │
│ 제4조(준용)    │   ① 회사는 … 〔갱신여부〕 … 【별표 1】 … │  · 조건 가지 판정       │
│ 제5조(소멸)    │     1. …                              │  · 슬롯 값 채움         │
│               │     2. …                              │  · 결과 문면            │
│               │  ┌ when: D0007 = 예 ────────────────┐  │                       │
│               │  │ ② …                             │  │  (편집 모드면 여기가    │
│               │  └─────────────────────────────────┘  │   고른 자리의 폼)      │
│  (조만 싣는다) │            명조 · 44em                 │                       │
└───────────────┴──────────────────────────────────────┴───────────────────────┘
   196px                    남는 폭                              360px
```

- **읽기 모드에는 본문에 조작이 하나도 없다.** 편집 모드에서만 행 오른쪽 끝에 아이콘이 붙는다 —
  `〔✎ 고치기〕 〔↑〕 〔↓〕 〔⧉ 복제〕 〔🗑〕`, 전부 tooltip 이 붙는다.
- 우측 패널은 **모드와 선택에 종속**된다.

| 상태 | 우측 패널 |
|---|---|
| 읽기 | 사전평가 · 미리보기 (`?view=eval` 이면 가지 판정 · 슬롯 값 · 결과 문면) |
| 편집 · 선택 없음 | 「문면 전체」 — 문서 제목 · 대응 보통약관 지정 · 조 추가 · 문면 삭제 |
| 편집 · 노드 선택 | 그 노드의 폼 + 이동 · 복제 · 삭제 (인라인 자리는 본문에 아이콘이 없어 여기서만 준다) |
| 편집 · 조건 가지 선택 | 「조건 가지」 — 조건식 · 가지 삭제 |
| 삭제 확인 중 | 확인 카드 하나가 패널을 통째로 차지한다 |

- 모드 · 선택 · 현재 조는 **전부 쿼리**(`?mode=edit&node=…&art=…&view=eval&confirm=…`)다. 클라이언트 상태가 없다.
- 사전평가는 **담보약관(특별약관)에만** 있다 — 보통약관은 담보 레벨 문맥이 없다 ([[06_결정/ADR-0011-보통약관문맥-기본계약]]).
- 목차는 **조만** 싣는다 (§2 L3 — 「목차는 이동 수단이지 구조 설명서가 아니다」).

> **그 변경은 `main` 에 없다** ([[06_결정/ADR-0033-별표코드-시스템채번]] 도 화면 반영 전).

- 그래프는 서버가 좌표까지 계산해 넘기고(`plot.ts`), 클라이언트는 **끌기 · 확대와 링크**만 맡는다
  ([[06_결정/ADR-0028-관계정보-그래프뷰]]).
- 조회 대상이 삭제된 코드여도 「삭제된 대상, 참조만 남았다」로 참조 목록은 보여준다.

## 22. 화면기획과 어긋난 것

**원인은 하나다 — 2026-09-09 화면 QA 1회차가 커밋되지 않았다.** 문서는 그 회차의 결론을 담고 있고,
`main` 의 코드는 그 전이다. 아래는 문서를 읽고 화면을 열었을 때 안 맞는 자리 전부다.

| 화면 | 화면기획 · QA 이력이 말하는 것 | `main` 의 실물 |
|---|---|---|
| 구분자 목록 | 컬럼 = 코드 · 표시명 · **유형 · 레벨 · 최종수정 · 수정자**, 노출 컬럼 없음 | 컬럼 = 코드 · 표시명 · **종류 · 레벨 · 노출**, 최종수정 · 수정자 없음 |
| 구분자 목록 | 폼은 목록에 안 나온다 (ADR-0031) | **폼이 그대로 나온다** · 종류 필터에도 「폼」이 있다 |
| 라벨 | `scalar` = 「일반」 · 필드명 「유형」 (ADR-0032) | `KIND_LABEL.scalar` = **「단일값」** · 필드명 **「종류」** |
| 구분자 생성 | 2열 그리드 · 폼 하나 + 서버 액션 교체 · 노출 라디오 · 설명 없음 · 제출은 헤더 우측 | `KindPicker` 가 폼 4벌을 `hidden` 으로 스위칭 · 노출 체크박스 · 설명 있음 · 제출은 폼 하단 |
| 구분자 생성 | 「선택지」는 타입이 선택형일 때만 | 라벨에 「(타입이 선택형일 때만)」이라 적힌 채 **항상 떠 있다** |
| 구분자 상세 | 1열 · `bareHead` · 코드가 첫 필드 · 사용처는 모달 · 설명 없음 | `.ts-l2-split` 2열 + 우측 aside 사용처 · 헤더에 이름 · 코드 · 사용처 · 설명 있음 |
| 구분자 상세 | 폼 코드로 들어오면 `/types/forms/<code>` 로 리다이렉트 | 리다이렉트 없음 — 읽기 전용 필드 표 + 「폼 탭에서 편집 →」 |
| 별표 | 조회형 표 + `/appendices/<code>` 상세 + `/appendices/new` + 코드 채번 (QA §C · ADR-0033) | 인라인 편집 표 + 목록 위 생성 폼 + **코드를 사람이 입력** |
| 목록 전반 | `ListPage` 공용 조각 · 최종수정 · 수정자 컬럼 확산 (QA §B) | 화면마다 `ListShell` 을 손으로 조립 · 컬럼 제각각 |
| 생성 화면 전반 | breadcrumb · 헤더 우측 제출 · 2열 그리드 · 접힌 「주석」 | 뒤로가기 없는 화면 다수 · 하단 제출 · 「설명」이 펼쳐진 채 |
| 공용 조각 | `FormRow` · `CreateHead` · `RadioGroup` · `Combobox` · `NoteField` · `UsageDialog` · `_lib/fieldType` | **`main` 에 없다** |
| 라벨 사전 | 구분자명 · 폼 이름 · 열거형변수 · 별표 이름 · 주석 · 유형 ([[02_UI/화면단어]]) | 화면은 전부 **표시명 · 선택지 · 설명 · 종류** |
| CSS | `.ts-field-static` · `.ts-field-card` · `.ts-crumb` | 없다. `.ts-l2-split` 은 구분자 상세가 아직 쓴다 |

**되돌리는 방향은 이 문서가 정하지 않는다.** 문서에 맞춰 코드를 올리는 일은
[[04_실행/화면일관성_작업지시]] 가, 화면기획 자체의 개정은 각 화면기획 문서가 맡는다.

## 23. 화면기획이 없는 화면

이 문서의 그림이 유일한 기록인 화면들. 화면기획을 쓸 때 여기서 출발한다.

- 로그인 (§3)
- 공용조항 목록 · 생성 · 상세 (§15) — 상세는 `EditShell` 을 안 쓰는 유일한 편집 화면
- 문면 목록 (§16) · **문면 저작 L3** (§17) — 앱에서 가장 큰 화면인데 화면기획이 없다
- 별표 (§18)
- 상품 목록 · 생성 · 상세 · 상품담보 값 · 조립 미리보기 (§19)
- 담보속성 (§20)

      후보 — ⓐ 화면 QA 회차마다 갱신 ⓑ 화면기획이 실물을 따라잡으면 이 문서는 폐기 ⓒ 그대로 둔다.

      레이아웃 유형 셋(§2) 중 어디에도 속하지 않는다.
