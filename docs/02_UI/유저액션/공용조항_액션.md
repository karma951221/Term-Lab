| ID | 결정 | 이유 | 대안 |
|---|---|---|---|
| D-P3-1 | 공용조항의 모드(inline/block)는 채번 후 불변 | 참조 노드 종류가 다르다(인라인 노드 vs 블록 자리 노드) — 모드가 바뀌면 기존 참조 자리가 전부 무효가 된다 | 사용처가 하나도 없을 때만 변경 허용 / 모드 변경 시 사용처 참조를 깨진 참조로 표시 |
| D-P3-2 | 삭제는 [[구분자_기획]] 잠정 규칙을 차용 — 프로덕션은 참조 중이면 거부, 개발 모드는 사용처 목록 확인 후 허용(참조는 깨진 상태로 남음) | 참조 무결성 규칙을 구분자와 한 벌로 유지. 모드 판정은 서버가 한다([[도메인모델]] §5) | 항상 거부 — 사용처를 먼저 전부 정리해야 삭제 가능 |
| D-P3-3 | 공용조항 복제를 액션으로 둔다 (본문·옵션 복사, 새 코드, 사용처 미승계) | 「큰 차이는 별도 공용조항으로 딴다」([[ADR-0008-공용조항]])의 실제 작업 경로가 기존 정의에서 출발하는 것이다 | 복제 없이 신규 작성만 — 사망형/일반형처럼 대부분 같은 본문을 매번 다시 쓴다 |
| D-P3-4 | 옵션 자리는 대안 2개 이상이어야 성립 | 대안 1개짜리 옵션은 선택이 없는 선택 — 조건식이나 본문 고정으로 표현해야 할 것이 옵션으로 새는 자리 | 대안 1개 허용 (「문구 있음 / 없음」을 대안 1개 + 미선택으로 표현) |
| D-P3-5 | 대안·옵션 자리 삭제는 프로덕션에서 사용 중이면 서버 거부, 개발 모드는 영향 목록 확인 후 허용 | [[ADR-0017-옵션-오버라이드]] §5는 재검사 목록만 정했을 뿐 삭제 가부를 정하지 않았다. 모드 규칙과 결을 맞춘다 | 모드와 무관하게 항상 허용하고 재검사 목록·조립 오류에만 의존 |
| D-P3-6 | 옵션 자리·대안의 표시 순서를 변경할 수 있다 | 선택 UI 의 나열 순서일 뿐이고, 저장이 코드 기반([[ADR-0005-코드-표시명-이중체계]])이라 기존 선택이 깨지지 않는다 | 순서 고정(생성 순) — 순서 변경 액션을 만들지 않는다 |
