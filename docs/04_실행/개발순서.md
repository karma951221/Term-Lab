## 원칙

1. **얇은 관통 먼저.** 모델링·에디터·조립 중 한쪽만 먼저 커지는 것을 막는다 —
   가장 단순한 사례로 입력부터 미리보기까지 뚫고, 그 다음에 넓힌다 (terms-lab 교훈 계승).
2. **관통의 종점은 화면 미리보기다.** `.docx` 는 MVP 밖 ([[범위]]).
3. **문면을 만들려면 재료가 먼저다.** 보통약관·담보약관을 만들기 위한
   구분자 · 담보 부착 구분자(파생 축 + 작명) · 공용조항이 문면 에디터보다 앞선다.
4. 기획은 구현보다 반 발만 앞선다. 다음 단계 착수 전에 그 단계의 기획만 확정한다.

## 단계 — ★ 관통 1 목표: 보통약관 + 일반상해사망(+추가) 특약 생성

### P0. 준비
- [x] 기술스택 결정 → [[03_설계/기술스택]]
- [x] 개발환경·리포 구성, 시드 경로 (2026-09-05 — 관통 1 시드)

### P1. 값의 기반 — 「폼 = 구조체」 실증
- [x] 구분자·enum 카탈로그 (정의 CRUD · 부착 5레벨 · const 포함)
- [x] 구조체 타입과 **필드 메타로 폼을 그리는 렌더러** (string·number·boolean·date·enum·list<enum> — list<T> 는 2026-09-01 MVP 제외)
- [x] 역할(관리자·편집자) 골격 — 파괴적 액션 서버 거부 원칙 (2026-09-04 모드 → 역할, ADR-0019)

### P2. 담보 마스터
- [x] 담보 > 세부보장 > 급부 트리 편집
- [x] 구분자 부착 + 값 입력 (P1 렌더러 재사용)

### P3. 공용조항
- [x] 정의: inline / block(항·항 목록) 모드 · 옵션(수동 선택) · 조건식 포함
- [x] 참조 전파 · 중첩 금지 → [[01_기획/공용조항_기획]]

### P4. 문면 에디터 — 담보약관 · 보통약관 마스터
- [x] 조·항·호·목 편집 + 조건 분기 (도메인·서비스 완료, 편집기 화면은 최소형) (if/elif/else · **인라인 포함**)
- [x] 공용조항 사용 (배치 순서 보존 · 옵션 선택)
- [x] 부분 사전평가 + 사전평가 뷰 ↔ 전체 뷰 토글
- [x] 보통약관 마스터 (여러 벌) + 조연결 최소형 — 준용 세부 규칙은 관통 후 (P7)

### P5. 상품과 탑재
- [x] 담보속성 카탈로그 (종류·유효값 · 속성별 담보명 규칙 — ADR-0015)
- [x] 상품 + 세목 (종·형 · 유형 구조체 폼 · 유효 조합 등록 — 명시 등록이 곧 제약)
- [x] 담보 탑재 = 담보 × 속성 조합 (유일) · 값 스냅샷 + 필드 단위 수정
- [x] 상품담보별 세목 부착 (유저 설정)
- [x] 작명 규칙 적용 + 수동 변경 · 기본계약 지정 (1개)

### P6. 조립 미리보기 → ★ 관통 1
- [x] 조건 해소(단계적 문맥) + 번호 계산 → 문서트리 → 화면 미리보기
- [x] 특약 그룹핑 (그룹 타이틀 + 하위 배치) · 별표 수집 (등장 순 번호)
- [x] 부분 조립 + 오류 마커·좌표 패널 (ADR-0016)
- [ ] **보통약관 + 일반상해사망보장 + 일반상해사망보장 추가** 를 생성해 원문과 대조 (눈 검증) — 축약 픽스처 스냅샷은 통과(2026-09-05), 실물 대조는 유저 몫
- [ ] 관통에서 드러난 누락·결함을 [[작업목록]]에 반영하고 P7 순서를 재조정

### P7. 넓히기 (관통 후 순서 재조정)
- [ ] **반복문** + 표 → 관통 2: 수술비(세부보장 7개)
- [ ] 파생 구분자 (식 편집 · 집계 6종 · 하위 트리 순회)
- [ ] 준용 규칙 세부 기획·구현 (조연결 위에)
- [ ] 별표 목록·본문 참조
- [ ] 종별 문구 메커니즘 (세목 존재 조건 + 종형명 치환)

### P8. 알파Plus 전체 재현 = MVP 완료
- [ ] 특약 10건 + 보통약관 전부 생성

## MVP 밖 (기록만)

- **산출물 스냅샷 회귀 비교** — 특정 시점 스냅샷 vs 현재 재산출 결과를 비교해,
  데이터 수정의 영향도를 회귀로 보는 기능. 문서트리가 순수 데이터라 이 기능의 기반이 된다.
