# 개발순서

> 상태: 초안 · 최종수정: 2026-08-30
>
> 지금 무엇을 만드는지는 이 문서 하나만 보면 되도록 유지한다.

## 원칙

1. **얇은 관통 먼저.** 모델링·에디터·조립 중 한쪽만 먼저 커지는 것을 막는다 —
   가장 단순한 사례로 입력부터 미리보기까지 뚫고, 그 다음에 넓힌다 (terms-lab 교훈 계승).
2. **관통의 종점은 화면 미리보기다.** `.docx` 는 MVP 밖 ([[범위]]).
3. **문면을 만들려면 재료가 먼저다.** 보통약관·담보약관을 만들기 위한
   구분자 · 담보 부착 구분자(파생 축 + 작명) · 공용조항이 문면 에디터보다 앞선다.
4. 기획은 구현보다 반 발만 앞선다. 다음 단계 착수 전에 그 단계의 기획만 확정한다.

## 단계 — ★ 관통 1 목표: 보통약관 + 일반상해사망(+추가) 특약 생성

### P0. 준비
- [ ] 기술스택 결정 → [[03_설계/기술스택]]
- [ ] 개발환경·리포 구성, 개발 모드 시드 경로

### P1. 값의 기반 — 「폼 = 구조체」 실증
- [ ] 구분자·enum 카탈로그 (정의 CRUD · 부착 5레벨 · const 포함)
- [ ] 구조체 타입과 **필드 메타로 폼을 그리는 렌더러** (string·number·boolean·date·enum·list<enum>·list<T>)
- [ ] 파생 축 구분자의 작명 메타 (값별 prefix/suffix · 조합 순서)
- [ ] 개발/프로덕션 모드 골격 (서버 거부 원칙)

### P2. 담보 마스터
- [ ] 담보 > 세부보장 > 급부 트리 편집
- [ ] 구분자 부착 + 값 입력 (P1 렌더러 재사용)

### P3. 공용조항
- [ ] 정의: inline / block(항·항 목록) 모드 · 옵션(수동 선택) · 조건식 포함
- [ ] 참조 전파 · 중첩 금지 → [[01_기획/공용조항_기획]]

### P4. 문면 에디터 — 담보약관 · 보통약관 마스터
- [ ] 조·항·호·목 편집 + 조건 분기 (if/elif/else · **인라인 포함**)
- [ ] 공용조항 사용 (배치 순서 보존 · 옵션 선택)
- [ ] 부분 사전평가 + 사전평가 뷰 ↔ 전체 뷰 토글
- [ ] 보통약관 마스터 (여러 벌) + 조연결 최소형 — 준용 세부 규칙은 관통 후 (P7)

### P5. 상품과 탑재
- [ ] 상품 + 세목 (종·형 · 유형 구조체 폼 · 유효 조합 등록)
- [ ] 담보 탑재 = 값 스냅샷 + 필드 단위 수정 + 다중 탑재
- [ ] 작명 규칙 적용 + 수동 변경 · 기본계약 지정 (1개)

### P6. 조립 미리보기 → ★ 관통 1
- [ ] 조건 해소(단계적 문맥) + 번호 계산 → 문서트리 → 화면 미리보기
- [ ] **보통약관 + 일반상해사망보장 + 일반상해사망보장 추가** 를 생성해 원문과 대조 (눈 검증)
- [ ] 관통에서 드러난 누락·결함을 [[작업목록]]에 반영하고 P7 순서를 재조정

### P7. 넓히기 (관통 후 순서 재조정)
- [ ] **반복문** + 표 → 관통 2: 수술비(세부보장 7개)
- [ ] 파생 구분자 (식 편집 · 집계 6종 · 하위 트리 순회)
- [ ] 준용 규칙 세부 기획·구현 (조연결 위에)
- [ ] 별표 목록·본문 참조
- [ ] 종별 문구 메커니즘 (세목 존재 조건 + 종형명 치환)

### P8. 알파Plus 전체 재현 = MVP 완료
- [ ] 특약 10건 + 보통약관 전부 생성

## MVP 밖 (기록만)

- **산출물 스냅샷 회귀 비교** — 특정 시점 스냅샷 vs 현재 재산출 결과를 비교해,
  데이터 수정의 영향도를 회귀로 보는 기능. 문서트리가 순수 데이터라 이 기능의 기반이 된다.
