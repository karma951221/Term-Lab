## 1. 개발 방식 — TDD

모든 작업 단위는 **테스트 먼저**다.

1. 기획·시나리오에서 규칙 하나를 고른다 → 실패하는 테스트를 쓴다 (`*.test.ts`, 설명은 한국어로 규칙을 그대로).
2. 통과하는 최소 구현 → 리팩터 → 다음 규칙.
3. 테스트 파일은 소스와 colocate (`src/**/X.test.ts`). 조립·평가·번호 계산은 **문서트리 스냅샷** (ADR-0009).
4. DB 를 타는 테스트는 **PGlite 인메모리** + `drizzle-kit/api` `pushSchema` 로 매 파일 새 DB (마이그레이션 파일에 의존하지 않는다).
5. 완료 기준: 해당 디렉토리 `npx vitest run <dir>` 녹색 + `npx tsc --noEmit` 통과 + `npx eslint <dir>` 통과.

  test-utils.ts        인메모리 PGlite + pushSchema 헬퍼                        [A2]
  repo/<area>.ts       저장소 접근 (drizzle 쿼리만)
src/services/<area>.ts 애플리케이션 서비스 — actor 검사 · 도메인 규칙 · repo 호출. 모든 쓰기의 진입점

- 한 에이전트는 자기 디렉토리만 만든다. 남의 디렉토리는 **읽기만**. 공유 파일(`types.ts`,
  `schema/index.ts`)은 **추가만** 하고 기존 줄을 바꾸지 않는다 — 바꿔야 하면 오케스트레이터에게 보고.
- 새 npm 의존성은 추가하지 않는다 (필요하면 보고). `overrides.typescript` 를 건드리지 않는다.
- 커밋은 오케스트레이터가 단계별로 한다. 에이전트는 커밋하지 않는다.

## 3. 공유 계약 (요약 — 상세는 코드 주석)

### 3.1 값 (types.ts)
- 필드 타입 6종: string · number · boolean · date(`YYYY-MM-DD`) · enum(코드) · list<enum>.
- `ValueSlot = {entered:true, value} | {entered:false}` — null 없음, 미입력은 상태.
- 코드는 시스템 채번 불변. 표시명 가변. 저장·식·참조는 코드만 쓴다.

### 3.2 식 언어 (expression) — ADR-0013 한 벌
- 참조: `<구분자코드>.<필드코드>` (구조체) · `<구분자코드>` (const·파생) ·
  내장 경로 `세부보장.이름`/`급부.이름` 류(뼈대 속성) · 담보속성 `attr.<속성종류코드>`.
- 리터럴: 문자열 `'…'` · 숫자 · `true/false` · 날짜 `d'2026-01-01'` · enum 값은 `'코드'` 문자열.
- 연산: `= ≠ != < <= > >=` · `and or not` · 괄호.
- 집계 6종: `any(p) all(p) sum(p) count(p) exist(p) notexist(p)` — 범위는 문맥의 하위 트리.
- 담보속성은 `exist(attr.X)` · `attr.X = '값'` · `attr.X ≠ '값'` 만 (RHS 리터럴만).
- 평가 결과: `{kind:'value', value}` | `{kind:'undetermined', reason}`(미결 — 문맥이 그 레벨을 모를 때, 사전평가용)
  | `{kind:'error', issue}`(미입력·미사용 속성·깨진 참조 → Issue + 좌표). 조용한 false 없음.
- 문맥(`EvalContext`)은 언어 밖 — 「경로 → ValueSlot | undetermined | missing」 조회 함수와
  「하위 트리 열거」 함수를 주입받는다. 별칭형 파생(`A = B`, 단일 참조만인 식)은 정의 시 거부.
- `extractRefs(expr)` 가 요구 구분자(경로 집합)를 돌려준다 (ADR-0010).

### 3.3 문면 노드 트리 (document) — ADR-0012
- 노드 종류(MVP): 구조 `document · article(조) · paragraph(항) · item(호) · subitem(목)` ·
  블록 동적 `condBlock(if/elif/else 가지) · forBlock · clauseBlockRef` ·
  인라인 `text · slot · inlineCond · inlineFor · articleRef · appendixRef · clauseInlineRef`.
- 허용 자식은 **규칙 테이블**(노드 종류 → 허용 자식 종류). 인라인 조건 중첩 금지, 블록 조건 중첩 허용.
- 조 메타는 조 명 · 조연결(대응 보통약관 조 id) 뿐. 번호는 저장하지 않는다.
- 저장은 문서 1건 = 트리 JSON 1건 (jsonb). 노드 id 는 트리 안에서 유일(uuid).

### 3.4 조립 산출 (assembly) — ADR-0016
- 입력: 상품 + 상품담보들 + 보통약관 템플릿 + 마스터 문면 + 공용조항 + 별표 마스터.
- 파이프라인: 문맥 구성 → 조건 해소(밟은 자리만) → 공용조항 참조 인라인화(옵션 해소: 오버라이드 > 마스터) →
  생략 판정(조연결 + 리터럴 비교, ADR-0014) → 조·항 번호 계산 → 참조 슬롯 해소 → 별표 수집(등장 순).
- 출력 `Booklet = { general: DocTree, specials: Group[], appendices: Appendix[], issues: Issue[], complete: boolean }`.
  오류는 마커 노드(`kind:'error'`)로 그 자리에 심고 계속 간다. `issues` 하나라도 있으면 `complete=false`.
- 특약 그룹 안 순서: 담보 → 담보속성 종류 → 유효값 오름차순 자동 정렬.

### 3.5 역할 (auth) — ADR-0019
- `Role = admin | editor`. 파괴적 액션(저장된 값·참조를 없애는 것)은 admin 만.
- 서비스의 파괴적 액션은 2단: 1차 호출 → `needsConfirmation`(Impact) 거부 → `confirm:true` 재호출 → 실행.
  최소 구조 위반은 admin 도 거부. 편집자의 파괴적 호출은 Impact 계산 전에 `forbidden`.
- MVP 인증: users 테이블 + 시드 admin 1명 + 쿠키 세션 최소형. 현재 사용자 조회는 `src/services/auth.ts`.

## 5. 관통 1 픽스처 (실물 축약)

- 구분자: `갱신여부`(담보, boolean, 무조건 노출) · `보험금지급`(급부, 구조체 {면책여부:boolean, 지급률:number}) ·
  `평균공시이율`(const string '2.5%') · `면책여부합`(담보, 파생 `any(보험금지급.면책여부)`) · `고지유형`(상품 enum).
- 담보속성: `부가유형` {기본, 추가} · `갱신유형` {비갱신형, 갱신형}.
- 담보: 「일반상해사망」 = 세부보장 1 · 급부 1. 문면: 제1조(보험금의 지급사유) · 제2조(보험금을 지급하지 않는 사유, `if 면책여부합`) ·
  제N조(특별약관의 소멸, 공용조항 block 참조 + 옵션) · 준용규정(공용조항 + 조연결 → 보통약관 조 참조 슬롯).
  인라인 조건: 「계약일」 vs 「최초계약일」(`attr.갱신유형 = '갱신형'`).
- 보통약관 마스터 1벌: 4~5개 조, 그중 하나가 별표 참조 슬롯(장해분류표).
- 상품 「알파Plus(축약)」: 상품담보 = 일반상해사망 × {기본} · × {추가}, 기본계약 = 기본. 그룹 「상해 관련 특별약관」.
- 기대: 특약 2벌(본문 동일, 제목만 다름) · 준용규정 조는 조연결 생략 판정 통과 · 별표 1건 번호 1 · issues 0.

## 6. 통합 절차 (오케스트레이터)

1. 단계마다 `npx vitest run` 전체 · `npx tsc --noEmit` · `npx eslint .` 녹색 확인 후 area 별 커밋.
2. D3 에서 `npm run db:generate` 로 마이그레이션 1벌 생성 (그 전 단계는 pushSchema 로만 검증).
