## 1. 작업 방식

- **TDD.** 규칙 하나 → 실패하는 테스트(한국어 설명, 시나리오 문장 그대로) → 최소 구현 → 리팩터. 테스트는 소스와 colocate.
- **완료 기준(모든 단계 공통)**: `npx vitest run` 전체 녹색 · `npx tsc --noEmit` · `npx eslint .` 통과.
  스냅샷 갱신은 `-u` 로 뭉개지 않는다 — diff 를 읽고 기대와 같을 때만 갱신하고, 커밋 본문에 무엇이 왜 바뀌었는지 적는다.
- **커밋은 단계(§4)마다, 아이템별로** 나눈다. 제목 = 무엇을, 본문 = 왜(결정·경위) + 임의 결정 목록. **Co-Authored-By 등 트레일러 금지.**
- 규칙 재확인: `src/domain/` 은 순수층(DB·React·Next import 금지, ESLint 강제) · 새 npm 의존성 금지 ·
  `package.json` 의 `overrides.typescript` 유지 · 표준 Postgres 만(PGlite 전용 기능 금지) ·
  **PGlite 트랜잭션 안에서 바깥 `db` 핸들 사용 금지**(영구 대기 — 아키텍처 §트랜잭션 규칙).
- 서비스 계층이 모든 쓰기의 진입점이다 — 시드·테스트도 repo 직접 쓰기 금지. 파괴적 액션은 기존 `destructive()` 프로토콜 그대로.
- 화면은 「기능이 도달 가능한 최소형」 유지. 레이아웃·디자인은 손대지 않는다.
- 저장된 문서 트리(jsonb)의 **하위 호환 변환기는 만들지 않는다** — 개발 DB 는 `.data/` 삭제 후 재시드로 갈아엎는다. 대신 시드·픽스처·스냅샷을 새 모양으로 고친다.

## 3. 공유 계약 변경 (`src/domain/types.ts` — 추가·확장만, 기존 필드 삭제 금지)

- `Issue.severity: "error" | "warning"` 추가. **warning 은 `Booklet.complete` 를 깨지 않는다.** 기존 오류는 전부 error.
- `Coordinate` 확장: ① 절/블록 이름공간 자리(예: `section?: {kind:"general"|"benefit"; label}` 류 — 0/2+ 모드에서 조 번호가 재시작하므로 조 앞 한 단계) ② 항·호·목 노드까지 가리킬 수 있어야 한다(`nodePath` 로 이미 가능 — 종류 표기용 `nodeKind?` 추가는 자유).
- `Issue` 에 **원천 좌표** 자리 추가(예: `source?: Coordinate`) — `at` 은 결과 자리, `source` 는 고치러 갈 곳. 원천이 여럿이면 첫 번째만. 오류 종류별 원천은 오류좌표_기획 §3 표 그대로.
- `IssueKind` 추가: 기본계약 2개 이상 등 「아직 지원하지 않는 모드」용 1종(이름은 자유, 예: `unsupported`), 「조연결 없는 기본계약 조」 warning 용 1종, 세목/슬롯 타입 거부는 기존 `typeMismatch` 재사용.
- 문서 노드(`src/domain/document/nodes.ts` · 같은 모양의 `clause/nodes.ts`):
  - `ArticleRefNode` → **다중 대상**: `targets: {nodeId: Id}[]`(대상 = 조·항·호·목 노드 id) + `connector: string`(기본 「및」) + 기존 `scope`. 한 덩어리의 대상은 같은 문서 안에서만.
  - `ClauseBlockRefNode` 에 `excludeFromComparison?: boolean` (「비교 제외」 — 보통약관 문서에서만 의미, 담보약관에서는 무시하되 저장은 허용).
  - `SlotNode` 는 그대로. **검증 규칙 추가**: 슬롯 참조의 타입이 string·enum 이 아니면 `typeMismatch` (저장 시 거부 + 편집기 후보 필터).

## 4. 단계와 순서

한 단계는 앞 단계가 녹색이어야 시작한다. S2·S3 는 S1 뒤 순서 무관.

### S1. 공유 계약 + 문서 노드 (domain/types · document · clause)
- §3 전부. `allowedChildren` 은 변경 없음.
- `document/refs.ts`(참조 수집) · `refs/`(참조 그래프) · `document/nodes.ts` 검증이 다중 대상 articleRef 를 대상 단위로 다룬다 — 깨진 대상은 **대상마다** `brokenRef`.
- 슬롯 타입 검증: `TreeEnv`/`TypeResolver` 로 참조 타입 조회 → string·enum 외 거부. 편집기(`src/app/(app)/documents`)의 슬롯 삽입 후보도 타입으로 거른다.

### S2. 작명 (domain/product/naming · schema · services/product · app/attributes)
- `attribute_values.prefix/suffix` → **`fragment` 하나**(빈 문자열 = 조각 없음). 카탈로그 전역 **칩 템플릿 1행** 저장소 신설(테이블 이름 자유, 예: `naming_templates`; 행 하나, 기본값 `[담보명]`).
- `defaultCoverageName(coverageName, selection, kinds, template)`: 칩 = `[담보명]` 또는 `[<담보속성 종류 표시명 또는 코드>]`(무엇으로 칩을 식별할지는 코드 — 표시명은 가변이다, ADR-0005). 치환 규칙은 ADR-0025 §결정 3 그대로(미사용·빈 조각·템플릿 밖 = 빈 문자열, 연속 공백 1칸, 앞뒤 정리). `AttributeKind.order` 는 **정렬에만** 쓴다.
- 서비스: 템플릿 조회·수정(편집자 가능 — 값 손실 없음), 유효값 조각 수정. 담보속성 카탈로그 화면에 템플릿 편집 칸 + **「템플릿에 없는 종류」 표시**.
- 검증 예: 템플릿 `[갱신유형] [담보명] [부가유형]`, 갱신형 + 추가 → 「갱신형 일반상해사망 추가」; 비갱신형(빈 조각) + 기본 → 「일반상해사망」.

### S3. 세목유형 4종 (시드 데이터만 — 도메인 변경 없음)
- plan 레벨 구조체 구분자 4개: 납입면제 `{적용여부: boolean, 납입면제사유: list<enum>}` · 무저해지 `{유형: enum{해약환급금지급형, 해약환급금미지급형, 해약환급금미지급형(납입후50%)}}` · 계약전환 `{전환여부: boolean}` · 영위업종적용 `{적용여부: boolean}`. 납입면제사유 enum 은 유저 정의 — 시드에는 예시 값 2개만.
- 세목 선택지·조합의 조작 흐름은 현행 구현 그대로(변경 없음). S7 의 JSON 시드에 함께 싣는다.

### S4. 준용·생략 + 기본계약 모드 (domain/assembly · domain/product · services/product · app/products)
- **섹션**: 담보 탑재 서비스가 `section: "base" | "special"` 을 받는다. base 면 `product_base_contracts` 행을 함께 만든다(기존 「기본계약 지정」 액션은 섹션 이동으로 흡수하거나 유지 — 임의). 상품모델링 화면은 두 섹션으로 나눠 보여주고 추가한다. MVP 검증 「기본계약 정확히 1개」는 조립·완결성에서 유지.
- **모드**: `AssemblyProduct.baseContractId` → `baseContractIds: Id[]` (단수 하드코딩 금지 — 범위 §구현 제약). 수 0 → 기존 `noBaseContract` 오류 유지, 2+ → 새 `unsupported` 오류(「기본계약 2개 이상은 MVP 이후」), 1 → 아래.
- **1개 모드 대치**: 기본계약 담보의 조 중 조연결된 것은 대응 보통약관 조 자리에 **그 조의 해소·치환 결과**로 대치(마스터 조는 빈 조여도 됨). 조연결 없는 기본계약 조 → **warning**(원천 = 담보 마스터 문면 그 조). 기본계약 담보는 특약 벌로 찍지 않는다(배치에서 제외, `undocumented` 도 아님 — 기록은 Booklet 에 남긴다, 이름 자유).
- **항 단위 판정**(`judgeOmission` 대체): 특약 조 ↔ (대치 후) 보통약관 조를 **항 단위** 직렬화로 비교 — 순서 무관 집합 매칭, 조 명 제외, 항 없는 조는 항 1개. 세 갈래 생략/준용/통째. 보통약관 조의 `excludeFromComparison` 인 block 참조가 만든 항은 비교 집합에서 뺀다. `OmissionRecord` 는 갈래(`omitted | applied | full`)를 갖는다.
- **준용 문장**: 「이 특별약관의 [담보 조 명]은/는 보통약관 제N조([보통약관 조 명])를 준용합니다.」 — 조사는 받침 자동, N 은 조립 계산값이므로 참조 슬롯과 같은 경로로 렌더(텍스트에 번호를 박지 않는다). 준용이면 제1항 = 이 문장, 이어서 보통약관에 없는 항만 원래 순서로.
- **준용규정 조 생성(최소형)**: 특약 문서 끝에 조 「준용규정」 1항 「이 특별약관에서 정하지 않은 사항은 보통약관을 따릅니다.」 를 조립이 붙인다. 문면에 준용규정 조가 있으면 검증 경고 없이 그대로 두되 시드에서는 뺀다. 제외 조 목록·종별 조건은 만들지 않는다(§7).
- 파이프라인 문서 주석(`assembly/types.ts` 머리)과 단계 표를 새 순서로 고친다.
- 완료: 관통 1 스냅샷이 §5 기대와 일치. 판정 세 갈래 + 비교 제외 + 대치 + warning 각각 단위 테스트.

### S5. 참조 슬롯 렌더 (domain/document/numbering · domain/assembly/render · app/documents)
- 렌더 표기는 문면_기획 §참조 슬롯 표 그대로. 규칙: 덩어리당 접두 「보통약관 」 한 번(scope general 일 때) · 대상은 쉼표 나열 + 마지막 앞 연결어 · 조 명 괄호 항상 · 항/호/목은 「같은 조면 제1항, 다른 조면 제N조(명) 제1항」 · 별표 `【별표N(이름)】` 단일 대상.
- 대상이 분기·생략으로 사라지면 **대상 단위** `articleGone`(마커는 덩어리 자리에 하나, issue 는 대상마다). 생략된 조를 가리키는 참조는 보통약관 쪽 조로 해소한다(생략 = 보통약관 조와 동일이므로).
- 편집 UI: 대상 트리 선택기(조 › 항 › 호 › 목, 같은 문서 / 대응 보통약관) + 연결어 칸 + 렌더 미리보기(마지막 번호 계산으로 표시, 저장은 id 만).
- `articleRefLabel` 류 헬퍼는 numbering 에 두고 render 는 조합만.

### S6. 오류 좌표 렌더러 + 패널 (domain 렌더러 · app/_components/IssueList · preview)
- 표시 문자열 렌더러 하나(`formatCoordinate` 류, 순수 함수): 오류좌표_기획 §4 규칙 — `›` 구분, 결과 자리는 `제N조(조 명) › ① › 종류:상세`, 원천은 번호 없이 조 명 + 「n번째 항」. 절/블록은 조 앞 한 단계.
- 오류 종류별 **원천** 채우기는 오류를 만드는 자리(평가·해소·치환·판정)가 한다 — 오류좌표_기획 §3 표. 값 원천은 `상품모델링 › 상품 › 상품담보 › 경로`.
- 패널(`IssueList` 확장): severity 구분 표시(warning 은 completeness 를 깨지 않음을 문구로) · **「미리보기에서 보기」**(결과 노드 id 앵커로 스크롤 — `RenderedDoc` 에 id 앵커) · **「고치러 가기」**(원천 화면 라우트 — 문면 편집기 `documents/[id]?node=` · 상품모델링 · 담보 마스터 · 공용조항 정의 · 담보속성 카탈로그).
- 같은 렌더러를 완결성 조회 · 공용조항 재검사 목록 · 관계정보 뷰 · Impact(brokenRefs) 표시에도 쓴다 (화면은 문자열 교체만).

### S7. 시드 JSON + 관통 1 픽스처 갱신 + 마이그레이션 + e2e
- `src/db/seed/data/*.json` — 영역별 파일(구분자·enum·담보속성·담보·공용조항·문면·보통약관·별표·상품). 참조는 전부 **코드**(uuid 없음), 문서 트리 안 노드 id 는 파일 안에서 사람이 읽을 수 있는 문자열이어도 되고 적재기가 uuid 로 바꿔도 된다 — 단 참조(조연결·articleRef)가 따라가야 한다.
- 적재기(`src/db/seed/load.ts` 류)는 파일을 읽어 **서비스 호출**로 넣는다. `alphaPlus.ts` 는 적재기 호출로 축소하거나 삭제. `src/domain/assembly/fixture.ts`(도메인 객체 픽스처)는 같은 JSON 에서 만들도록 통일해도 되고 손으로 동기화해도 된다 — 둘이 어긋나지 않게 **한 테스트가 두 결과를 대조**한다.
- `npm run db:generate` 로 마이그레이션 `0001` 생성(S2 스키마 변경). 0000 은 손대지 않는다.
- Playwright 스모크(`tests/e2e/smoke.spec.ts`) 갱신: 로그인 → 상품 → 미리보기에 대치된 보통약관 조 + 특약 2벌 + 오류 패널 0건.
- 픽스처 내용은 §5.

## 5. 관통 1 픽스처 (갱신 — 실물 축약)

2차구현_계획 §5 의 픽스처를 다음처럼 바꾼다. ADR-0021 로 **기본계약 담보는 특약으로 찍히지 않으므로**, 「특약 2벌(본문 동일·제목만 다름)」 실증을 지키려면 기본계약 담보가 일반상해사망과 **별개**여야 한다.

- 담보 3 탑재: **기본계약 담보 1**(§7 잠정 이름 「상해사망(기본계약)」 — 세부보장 1 · 급부 1, 문면: 제1조(보험금의 지급사유) · 제2조(보험금 지급에 관한 세부규정), 둘 다 보통약관의 빈 조 「보험금의 지급사유」·「보험금 지급에 관한 세부규정」에 조연결) + 「일반상해사망」 × {기본} · × {추가} (특약 섹션, 그룹 「상해 관련 특별약관」).
- 보통약관 마스터: 용어의 정의 · 보험금의 지급사유(빈 조, 대치 자리) · 보험금 지급에 관한 세부규정(빈 조, 대치 자리) · 보험금을 지급하지 않는 사유(항 2개, 그중 하나는 block 공용조항 참조에 **비교 제외** 켬) · 장해의 분류(별표 참조 슬롯) · 해약환급금(항 2개 — 항 참조 대상). **준용규정 조 없음.**
- 일반상해사망 특약 문면: 제1조 지급사유(통째) · 제2조 지급하지 않는 사유(`if 면책여부합`, 조연결 → 보통약관 같은 조; 본문은 비교 제외 항을 뺀 나머지와 동일 → **생략**) · 제3조 감액지급(조연결 → 보통약관 해약환급금 조; 보통약관 항 전부 포함 + 항 하나 더 → **준용** + 추가 항) · 제4조 특별약관의 소멸(block 공용조항 + 옵션) · 인라인 조건 「계약일/최초계약일」(`attr.갱신유형`) · 참조 슬롯 덩어리 1개(보통약관 해약환급금 조 제1항 및 제2항 — 항 참조) · 별표 참조 없음. **준용규정 조 없음(조립이 붙인다).**
- 값 슬롯: `평균공시이율`(const string) 유지. **`감액기간`(D0006, number)은 슬롯에 못 찍는다(ADR-0024)** → 문면용 string 구분자로 갈아끼운다(number 는 남겨도 됨).
- 세목: S3 의 4 유형 정의 + 알파Plus(축약)에 종 축 선택지 「1종(보험료 납입면제 미적용형)」·「2종(보험료 납입면제 적용형)」(납입면제 값 입력) + 조합 2건 등록. 상품담보 부착은 하지 않는다(P7).
- 작명: 템플릿 `[갱신유형] [담보명] [부가유형]`, 조각 갱신형→「갱신형」, 비갱신형→「」, 기본→「」, 추가→「추가」. 기대 이름 「일반상해사망」·「일반상해사망 추가」.
- **기대 Booklet**: 보통약관(지급사유·세부규정 조가 기본계약 조 내용으로 대치) · 특약 2벌(제1조 통째 · 제2조 생략 · 제3조 준용 문장 + 추가 항 · 제4조 · 조립이 붙인 준용규정, 본문 동일·제목만 다름) · 별표 1건 번호 1 · issues 0(warning 0) · complete true · 참조 덩어리 렌더 「보통약관 제6조(해약환급금) 제1항 및 제2항」(번호는 실제 계산값으로).

## 6. 통합 절차

1. 단계마다 §1 완료 기준 확인 후 영역별 커밋. 커밋 본문에 임의 결정·발견 사항을 남긴다(리뷰 세션이 그것을 읽는다).
2. S7 에서 `.data/` 를 지우고 `npm run db:seed` 가 마이그레이션 → 적재 → 조립 검증(complete)까지 통과하는지 확인.
3. 마지막 커밋(S8)에 문서 갱신. 끝나면 `git log --oneline` 과 임의 결정 목록을 요약해 보고한다.

## 7. 잠정 결정 (유저 확인 대상 — 구현은 이대로 진행)

- **준용규정 조 최소형**: 상세는 MVP 이후지만 「문면에 쓰지 않는다」가 확정이라 한 문장짜리 조를 조립이 붙인다. 제외 조 목록·종별 조건 없음. 문장은 실물 확인 후 바뀔 수 있다.
- **기본계약 담보를 별개로**: 픽스처에 「상해사망(기본계약)」 담보를 추가한다 — 이름은 임시. 실물 알파Plus 의 기본계약 담보명으로 유저가 바꾼다.
- **감액기간 슬롯**: number 구분자를 문면에 찍던 자리를 string 구분자로 대체(ADR-0024 의 「두 필드」 사례).
- **칩 식별자**: 템플릿 칩은 담보속성 **코드**로 저장하고 편집기가 표시명으로 보여준다(ADR-0005).
- **탑재 섹션 저장**: 별도 컬럼 없이 `product_base_contracts` 행 유무가 섹션이다(관계로 모델링, 단수 하드코딩 금지).
- **기본계약 담보 2개 이상**: 조립은 `unsupported` 오류 하나로 멈추지 않고 나머지를 계속 조립한다(부분 조립 원칙).
