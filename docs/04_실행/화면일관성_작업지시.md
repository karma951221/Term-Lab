# 화면 일관성 작업지시 (2026-09-09 이후)

> 상태: 초안 · 최종수정: 2026-09-09
>
> 대상: 2026-09-09 화면 QA 1회차에서 **손대지 않은 화면들**.
> 근거: [[05_QA/화면QA_이력]] (굳은 규칙 R1~R17 · 되돌린 시도 U1~U6) · [[02_UI/화면단어]] (라벨 사전).

구분자 탭 · 목록 화면 공통화 · 별표 화면은 끝났다. 나머지 화면을 **같은 규칙으로** 맞춘다.
새 판단을 하지 말고 이미 굳은 것을 적용한다 — 규칙과 어긋나야 할 이유가 나오면 그때 멈추고 묻는다.

## 0. 먼저 읽을 것

1. [[05_QA/화면QA_이력]] — 규칙 R1~R17, 되돌린 시도 U1~U6 (**같은 길을 다시 걷지 않도록**)
2. [[02_UI/화면단어]] — 라벨 사전
3. [[02_UI/디자인원칙]] §2 (L1 조회 · L2 수정) · §9 (결정 부담)

## 1. 라벨 통일 — 전 화면

[[02_UI/화면단어]] 대로. 문자열을 화면에 직접 적지 말고 `src/app/_lib/labels.ts` 를 통과시킨다 (규칙 R4).

| 고칠 것 | 어디 |
|---|---|
| 이름 칸을 **실체별 한 라벨**로 | 목록 `nameCol` · 생성 `FormRow` · 상세 `Field` 가 한 화면에서 다른 말을 쓰지 않게 |
| 「선택지」 → **열거형변수** | 내비 하위탭 · 폼 목록 컬럼 · enum 목록/상세/생성 · 「선택지 고르기」 |
| 「설명」 → **주석** | 별표 목록 컬럼 · 열거형변수 편집 · 그 밖 남은 자리 |
| 「종류」 → **유형** | 담보속성 |
| 「표시명」을 화면에서 제거 | 도메인 용어라 화면에 안 쓴다 |

**「목록값」과 「열거형변수」를 합치지 말 것** — 앞은 타입 이름, 뒤는 실체 이름이다 (사전 참고).

## 2. 화면별 — 실제로 보고 확인한 것

### 2.1 담보속성 (`/attributes`) — 가장 밀렸다

한 페이지에 **템플릿 편집 + 새 종류 생성 폼 + 종류별 인라인 편집(표시명 칸 + 저장 버튼)** 이 전부 펼쳐져 있다.

- **R17 위반** — 목록에서 인라인 편집하고 있다. 목록은 고르는 자리, 고치는 자리는 상세다.
  → L1 목록(`ListPage`) + `/attributes/<code>` 상세로 가른다. 별표(§C)가 같은 전환의 선례다.
- 생성 폼이 목록 중간에 박혀 있다 → `+` 아이콘 → 별도 생성 화면 (§2 L1).
- 저장 버튼이 섹션마다 흩어져 있다 → 헤더 우측 하나 (규칙: 화면 하단·중간에 조작을 두지 않는다).
- 「종류」 → 「유형」, 「표시명」 → 「담보속성명」.
- 상품담보명 템플릿은 담보속성 목록과 **다른 것**이다. 한 화면에 쌓지 말고 자리를 가른다.

### 2.2 열거형변수 상세 (`/types/enums/<code>`)

- 헤더에 **이름 · 코드 · 사용처가 그대로 있다** — 구분자 상세에서 뺀 것(A10)과 같은 문제.
  → `bareHead` + **코드를 첫 필드**로.
- 사용처가 헤더의 글자다 → **`UsageDialog` 모달**로 (규칙 R9, 구분자 · 별표가 이미 쓴다).
- 「표시명」 → 「열거형변수 이름」.
- 값 표의 인라인 편집은 **남겨도 된다** — 값은 이 실체의 부품이지 별도 실체가 아니다 (폼의 필드 표와 같은 결).

### 2.3 새 공용조항 (`/clauses/new`)

- **뒤로가기가 없다** → 제목 줄 breadcrumb 「공용조항 › 새 공용조항」 (U4 에서 정해진 모양).
- 「표시명」 → 「공용조항명」.
- **본문을 JSON 원문 textarea 로 받는다.** 현업이 채울 수 있는 칸이 아니다.
  → 이건 별개의 큰 작업이라 **이 지시의 범위 밖**. 손대지 말고 그대로 둔다.
- 주석 아이콘이 라벨 없이 본문 아래에 홀로 서 있다 → 어느 칸인지 보이게 (`FormRow` 안으로).

### 2.4 새 별표 (`/appendices/new`)

- 뒤로가기 없음 → breadcrumb.
- 「이름」 → 「별표 이름」.
- 주석 아이콘이 라벨 없이 떠 있다 (2.3 과 같은 문제).

### 2.5 그 밖 생성 화면 전부

- **breadcrumb** 「<목록> › 새 <실체>」 · **제출은 헤더 우측** · **2열 그리드** (U1 · U4).
- **중요한 칸이 위에.** 이름 → 그 실체를 가르는 값 → 나머지 → 주석(접힘).
  구분자가 「구분자명 → 레벨 → 유형 → 타입 → 노출」인 것과 같은 결.
- 조건부로 나타나는 칸은 **딸린 자리에 카드**(`.ts-field-card`)로 묶는다 (R8).
  평범한 필드 하나를 카드로 싸지는 않는다 (U3).
- 안 쓰는 칸은 `hidden` 이 아니라 **뺀다** (R7).

### 2.6 그 밖 상세 화면 전부

- 헤더에 이름 · 코드 · 메타를 세우지 않는다 → `bareHead` + 코드를 첫 필드 (A10).
- 여기서 아예 못 고치는 값은 `.ts-field-static`(글자), 읽기 모드의 값은 `.ts-field-locked`(회색 칸) (R5).
- 사용처는 `UsageDialog` 모달, **편집 모드에서는 감춘다** (R9).

## 3. 하지 말 것

- **U1~U6 을 다시 시도하지 말 것** — 1열 스택 · 중요도 2단 · 평범한 필드의 카드 · 뒤로가기 별도 줄 · 부가 단의 작은 설명 칸.
- 도메인 · 저장소 · 시드 · E2E 는 건드리지 않는다. 이 지시는 **화면과 라벨**까지다.
- 공용조항 본문 편집기(JSON) 는 범위 밖.
- 새 레이아웃 유형을 만들지 않는다 — 필요하면 [[06_결정]] 에 ADR 이 먼저다 (§2 「유형 3개가 전부」).

## 4. 끝났다고 말하려면

- `npx tsc --noEmit` · `npm run lint` · `npm test` 가 전부 통과.
- 고친 화면을 **실제로 띄워** 확인한다. 생성 화면은 만들고 지우는 왕복까지.
- 화면기획([[02_UI/화면목록]])과 [[05_QA/화면QA_이력]] 2회차에 반영. 별표는 화면기획 자체가 아직 없다.
